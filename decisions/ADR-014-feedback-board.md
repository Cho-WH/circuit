# ADR-014: 익명 후기 게시판과 백엔드 교체 경계

- 상태: accepted
- 결정일: 2026-09-23
- 요구사항: DAT-005, QLT-001

## 배경

MVP 이후 사용자가 교사 후기·피드백 게시판을 요청했다. 로그인을 직접 요구하지 않고 자유 닉네임, 관리 비밀번호, 공개 범위, 하루 3회 작성 및 삭제 기록 보관이 필요하다. Firebase 연결은 후속 작업이다.

## 결정

- `feedback`은 React·브라우저·Firebase와 무관한 타입, 검증, `FeedbackGateway`와 별도 `FeedbackAdminGateway` 계약을 공개한다. `CircuitDocument`에는 게시판 상태를 넣지 않는다.
- 현재 `feedback-local`이 버전 1 로컬 저장소와 자동 익명 ID로 계약을 구현한다. 실제 Firebase Anonymous Auth는 연결하지 않았다. Web Locks로 브라우저 탭 간 저장·한도 검사를 직렬화하며 미지원 환경은 구조화된 실패를 반환한다.
- 하루는 한국 표준시 00:00 경계다. 공개·비공개·삭제 글 모두 한도에 포함한다. 횟수·잔여 한도는 UI에서 안내하지 않고 거부 시 일반적인 작성 제한 메시지만 표시한다.
- 관리 비밀번호는 4~128자, 닉네임은 공백 제외 1~20자, 본문은 1~2000자다. 비밀번호는 평문 저장하지 않으며 로컬 검증 자료는 글별 16바이트 salt와 PBKDF2-SHA256 210,000회 결과다. 비밀번호는 본인 브라우저에서도 삭제에 필수다.
- `remove`는 원문을 지우지 않고 `deletedAt`을 기록한다. 공개 목록과 본인 목록에서 제외하며 관리자 조회만 삭제 원문을 반환한다. 보관 사실은 작성·삭제 전에 알린다.
- 공개 목록에 비공개 글의 자리표시자나 총 건수를 노출하지 않는다. DTO에는 인증 ID·salt·해시가 없다. 관리자 포트는 일반 사용자 포트와 분리한다.
- 사용자 후속 요청으로 게시판 내부 관리자 미리보기를 제거하고 별도 `/admin/feedback/` 문서로 분리한다. 개발 환경에서는 로컬 관리자 포트를 주입한다. 운영 빌드는 관리자 포트 미연결 상태로 기록을 표시하지 않는다. 운영 관리자 인증과 원격 권한 검사는 후속 어댑터의 필수 조건이다. Vite 다중 페이지 빌드로 정적 호스팅에서도 경로 직접 접속·새로고침을 지원하며 GitHub Pages에서는 `/circuit/admin/feedback/`다.

## 결과 및 한계

- 현재 브라우저 저장소는 보안 경계가 아니다. 사용자가 데이터·시계·익명 ID를 변경할 수 있으며 다른 기기나 관리자에게 실제 전송되지 않는다. 로컬 미리보기임을 화면에 명시한다.
- 원격 어댑터는 서버에서 익명 인증, 서버 시각, 원자적 할당량, 비밀번호 확인, 삭제, 관리자 권한을 강제해야 한다. 브라우저에서 해시를 읽어 삭제 권한을 판단하는 방식은 채택하지 않는다.
- 공개 게시판을 실제 운영하려면 비밀번호 검증 요청 제한도 필요하다. 프런트엔드 버튼 제한만으로 보장하지 않는다.
- 회로 저장 형식은 바뀌지 않으므로 CircuitDocument 마이그레이션은 없다. 게시판 저장은 별도 키/버전이며 손상되거나 지원하지 않는 버전은 덮어쓰지 않는다.
- 기존 물리 규칙·fixture 적용 없음. 계약과 React 통합 테스트 및 데스크톱·모바일 브라우저 검증으로 확인한다.
