# ADR-014: 익명 후기 게시판과 백엔드 교체 경계

- 상태: accepted
- 결정일: 2026-09-23
- 요구사항: DAT-005, QLT-001

## 배경

교사 후기·피드백을 로그인 조작 없이 받고 자유 닉네임, 공개 범위, 하루 3회 작성, 수정·삭제 및 관리자 삭제 기록 보관을 제공한다. 사용자 후속 요청에 따라 비밀번호 관리를 브라우저 익명 인증으로 교체하고 하나의 Firebase Spark 프로젝트를 로컬·GitHub Pages에서 함께 사용한다. Analytics는 사용하지 않는다.

## 결정

- `feedback`은 React·브라우저·Firebase와 무관한 타입, 검증, `FeedbackGateway`와 별도 `FeedbackAdminGateway`를 공개한다. 회로 문서에는 게시판 상태를 넣지 않는다.
- 운영 UI는 `feedback-firebase` 어댑터를 사용한다. `feedback-local`은 기존 미리보기 자료·fixture 호환 검증용으로 유지하며 원격 실패 시 로컬 저장소로 자동 전환하지 않는다. 기존 자료와 로컬 ID를 운영 서버로 자동 이전하지 않는다.
- 하루는 한국 표준시 00:00 경계다. 공개·비공개·삭제 글 모두 한도에 포함한다. 수정은 횟수를 소모하거나 환급하지 않는다. 횟수·잔여 한도는 안내하지 않고 거부 시 일반적인 제한 메시지만 표시한다.
- 닉네임은 앞뒤 공백을 제거한 뒤 1~20자, 본문은 1~2000자다. 비밀번호 필드·검증을 제거한다. `update`·`remove`에서 현재 익명 ID와 원문 작성자 ID의 일치를 검사한다. `canManage` 응답은 버튼 표시용이며 권한 근거로 신뢰하지 않는다.
- 수정은 닉네임·내용·종류·공개 범위만 바꾸고 `updatedAt`을 기록한다. 작성자·ID·최초 작성 시각을 유지한다. 삭제는 `deletedAt`을 기록하여 공개·본인 목록에서 제외하고 관리자에게 마지막 내용을 보존한다. 보관 사실은 작성·삭제 전에 알린다.
- 같은 브라우저에서만 수정·삭제할 수 있다는 한 줄 안내와 물음표 상세 안내를 제공한다. 상세에는 사이트 데이터·시크릿 모드로 인증 정보가 사라질 수 있다는 설명과 관리자에게 별도로 삭제 요청하는 방법을 담는다. 터치·키보드로도 읽고 닫을 수 있다.
- 공개 목록에는 비공개 글 자리표시자·건수·작성자 UID를 노출하지 않는다. 관리자 포트는 일반 포트와 분리하며 별도 `/admin/feedback/` 페이지에서 Google 로그인과 서버 허용 목록을 검사한다. 로컬 실행에서도 같은 운영 프로젝트를 사용한다.
- Firebase 앱 이름 `feedback-browser`와 `feedback-admin`으로 Auth 세션을 분리한다. 관리자 로그인·로그아웃은 익명 글 소유권에 영향을 주지 않는다. 인증 정보는 사이트 origin별 브라우저 저장소에 유지하므로 로컬과 GitHub 주소의 작성자 ID는 별개다.
- 로컬 v1→v2 이전은 작성자·공개 범위·삭제 기록을 보존하고 새 자료에서 비밀번호 검증 필드를 제거한다. v1은 복구용으로만 보존한다. 손상·미지원 v2는 덮어쓰지 않는다. 회로 저장 형식은 변경하지 않는다.

## 결과 및 한계

- Spark 연결은 익명 Auth·Firestore·보안 규칙으로 설계하고 Cloud Functions를 필수로 두지 않는다. 작성자 변경 금지, 허용 필드, 서버 시각, 원자적 작성 할당량, 원문·공개 사본 동기화와 관리자 권한은 규칙으로 강제한다. 구체적인 연결·검증 조건은 [게시판 구조](../docs/architecture/feedback.md)에 기록한다.
- Firebase 원문·공개 사본·불변 할당 슬롯을 Security Rules와 트랜잭션으로 보호한다. 서버 시각의 한국 날짜를 검증하고 경쟁 중 다른 글이 슬롯을 선점한 경우에만 제한된 재시도를 한다. 단위 보안 검증은 demo Firestore 에뮬레이터에서 수행한다. 실제 배포 상태는 [설정 기록](../docs/implementation/firebase-setup.md)에 별도로 기록한다.
- 브라우저 인증 정보가 지워지면 본인 권한을 복구할 수 없다. 관리자 별도 요청으로 안내한다. 로컬 ID와 향후 Firebase UID는 자동으로 연결하지 않는다.
- 물리 계산·회로 fixture 변경은 없다. 게시판 계약·이전 fixture·React 통합 테스트와 실제 브라우저 조작으로 검증한다.
