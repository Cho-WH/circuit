# ADR-027: 안정판·개발판 배포와 브라우저 저장 분리

- 상태: accepted
- 결정일: 2026-10-06
- 관련 요구사항: DAT-001, DAT-002

## 배경

수업에는 다이오드 추가 직전의 안정판을 유지하고, 다이오드와 이후 변경은 별도의 개발판에서 확인한다. GitHub Pages는 한 저장소의 사이트 전체를 한 번에 교체하며 같은 도메인의 경로들은 localStorage를 공유한다.

## 결정

- `main`은 안정판, `dev`는 개발판으로 상시 유지한다. 최초 main 기능 기준은 `6c44400`이다. 기능 승격은 dev→main 병합으로 수행한다.
- `VITE_RELEASE_CHANNEL`의 main/dev가 배포 경로와 브라우저 저장 이름을 함께 결정한다. 로컬 기본값은 dev이며 다른 지정값은 빌드 오류로 거부한다. 문서 형식과 채널은 별개다.
- 어느 브랜치든 푸시하면 양쪽을 검증·빌드하고 main 산출물 루트와 dev 산출물의 `/dev/`를 합쳐 단일 Pages artifact로 배포한다. 한쪽 실패 시 이전 배포를 유지한다. 환경 배포 권한은 main/dev에만 둔다.
- `release` 공개 모듈이 저장 키에 `main:`/`dev:`를 붙인다. 자동 저장·보관·측정 기록·백업·첫 안내·로컬 후기 미리보기가 이를 재사용한다. core 계산 모듈은 이 모듈에 의존하지 않는다.
- 기존 공용 키는 현재 채널 키가 없고 해당 형식의 검증을 통과할 때만 복사한다. 원본은 삭제하지 않는다. 이미 존재하는 채널 저장본과 빈 측정 기록을 공용 키로 덮어쓰지 않는다. 다른 채널의 값은 읽지 않는다.
- 파일 스키마와 지원 버전은 각 브랜치의 계약을 따른다. 최초 main은 회로 v5·기록 v4, dev는 회로 v6·기록 v5다. 형식을 자동 변환하거나 CircuitDocument에 채널·계산·UI 상태를 추가하지 않는다. JSON 파일도 채널과 무관하게 형식으로 검증한다.
- Firebase 운영 후기·인증의 프로젝트는 공유한다. 회로 저장 분리를 위해 별도 백엔드나 배포 서비스는 추가하지 않는다.

## 결과와 검증

같은 브라우저에서 양쪽 앱을 사용해도 저장본·측정 기록과 복구본을 서로 덮어쓰지 않는다. 안정판 승격 후에도 기존 main 저장 공간을 사용하며 지원 버전이 바뀔 때의 거부 정책은 유지된다.

`tests/release-storage.test.ts`가 동일 저장소에서 양쪽 쓰기·읽기·손상 복구·빈 기록·기존 데이터 복사를 확인한다. 배포는 채널별 자산 경로와 `release.json`의 실제 커밋으로 확인한다. 운영 절차는 [개발 운영](../docs/operations/development-workflow.md)을 따른다.
