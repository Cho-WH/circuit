# ADR-043 선형 RC 순수 엔진 연결과 도선 질의

- 상태: accepted
- 작성일: 2026-10-22
- 관련 요구사항: SIM-001, SIM-009, MEA-006. ADR-041/042의 C2 구현 결정
- 승인 범위: 사용자가 dev의 C2 구현·검증을 요청했다. C3 재생·명령 세션, C4 화면·기록 UI, C5 배포 수용은 포함하지 않는다.

## 결정

simulation 공개 index의 `rcEngine`으로 `prepare`, `sample`, `queryVoltage`, `queryCurrent`, `queryWireCurrent`를 제공한다. 입력은 C1의 CompiledCircuit과 단자 ID별 축전기 시작 상태이며, 기존 DC solve·작동 경계 경로는 바꾸지 않는다. 축전기 없는 회로는 기존 DC 엔진을 사용하고 RC 엔진은 축전기 없는 요청을 거부한다. RC의 저항성 부하·전류계·전압계·전원은 ADR-041의 이상적 모델이며 DC 프로필·내부저항·파손 판정을 적용하지 않는다.

C0 수치 코드를 simulation 내부의 `rc/`로 옮겨 제품 경계를 붙였다. tools/rc-prototype은 C0 결과를 재현하는 고정 기준으로 남긴다. 제품 코드는 tools를 import하지 않는다. 이후 제품 수정은 src에 반영하고 고정 C0와 독립 90자리 기준 비교로 확인한다. 외부 수치 코드·의존성은 추가하지 않았다.

## 요청과 실행 객체

`rcCircuitRevision(compiled)`는 정렬된 net·단자/도선 ID·전기값·방향·기준점·도선 질의의 정규 JSON을 반환한다. 해시 충돌을 피하기 위해 전체 정규형 문자열을 사용한다. 화면 위치·이름·DC 프로필은 제외한다. prepare는 이 값과 요청의 circuitRevision을 대조한다. `rcInitialState(compiled)`는 문서 초기 전압의 복사본을 만든다. 두 보조 함수의 입력은 정상 컴파일 결과다. 검증되지 않은 요청의 최종 거부 경계는 prepare다.

initial 요청은 문서 초기값과 일치해야 하고 operation 요청은 이전 상태를 부품·a/b 단자 ID로 매핑한다. 단자 ID가 정확히 뒤집힌 상태는 부호를 바꿔 매핑한다. 누락·중복·서로 다른 단자는 거부한다. 유효한 상태에서 추가 조작을 허용하는 조건, C·문서 구조 변경 금지는 C3 명령 계층이 담당한다.

C2는 정확 초기 상태·정확 평형의 승계를 지원한다. 유한 시각의 근사 전압을 다음 구간의 초기값으로 넘기면 `RC_NUMERICAL_UNVERIFIED`의 `approximate-input` 사유로 거부한다. 근사 상태의 오차 전파를 구현한 것처럼 값을 정확값으로 바꾸지 않는다. 승인된 UX는 평형에서만 다음 조작을 허용하므로 정상 흐름은 이 경계를 넘지 않는다.

plan/frame은 엔진 소유 객체를 WeakMap으로 식별하고 공개 결과를 깊게 동결한다. 입력 문서를 복사하여 호출자의 이후 수정이 준비된 해를 바꾸지 않게 한다. 복사·역직렬화하거나 다른 객체로 만든 plan/frame은 질의에 사용할 수 없다. 동일 전기 입력·조작·시각의 frame ID는 재현되며 시각 객체의 필드 순서와 -0에 영향받지 않는다. 엔진에 시계·네트워크·저장·UI 의존을 넣지 않는다.

## 도선과 비유일성

connectivity는 축전기 문서에만 `CompiledCircuit.wireCurrentTerms`를 추가한다. 도선 하나를 이상적 도선 그래프에서 잘랐을 때 시작점 쪽 단자 전류의 KCL 합을 기록한다. 별도의 도선 경로가 남으면 null로 표시한다. 축전기 a/b, 전원 극성, 전환 스위치의 선택 접점과 비선택 접점의 0 전류를 반영한다. 이 값은 컴파일 결과이며 회로 파일에는 저장하지 않는다.

엔진은 개별 가지의 임의 대표 전류를 공개하지 않는다. 이상적 전압원·0 Ω 고리의 전류 자유도를 보존한 채 질의의 정수 계수 선형합이 그 자유도를 소거하는지 정확히 검사한다. 개별 전류가 미정이어도 합계가 유일하면 값을 반환한다. 정확한 KCL 소거는 근사 잔차가 아니라 정확한 0으로 반환한다. 도선 고리는 계속 미정이다.

정의 가능한 도선 전류도 prepare의 관측량과 안정화 상한에 포함한다. `RcFrame`에 wireCurrents·undefinedWireCurrentIds를 추가하고 RcEngine에 queryWireCurrent를 추가한다. 전압 질의는 이미 계산한 두 net 사이의 직접 응답을 사용하여 큰 공통 전위를 뺄 때의 오차 확대를 피한다. 동적 연결로 묶인 기준 안에서만 비교한다.

RcReading은 기존 unique/undefined에 `{status:'error', diagnostics}`를 추가한다. 잘못된 객체·입력, 예산 소진, 수치 미확인은 물리적 비유일성과 구분한다. 임의의 전류 합 질의는 매 호출 독립 예산으로 인증하므로 앞선 질의 횟수에 따라 실패하지 않는다. prepare에서 등록하지 않은 임의 조합의 개별 안정화 시각까지 plan.summary가 보장하지는 않는다. 화면에서 사용하는 부품·도선 전류와 모든 같은 기준 net 전압차는 준비된 관측량에 포함한다.

## 계산 정책과 저장 경계

`rc-modal-1`·`rc-envelope-1`을 사용한다. 정확 제약 축약·보존 전하·평형, 대칭 감쇠 후보와 잔차 에너지 상한, 바깥 반올림 지수 구간, 수치 예산 1%는 C0에서 검증한 규칙을 유지한다. 근사 Rational의 중심은 binary64의 정확한 분수로 저장하고 rc-modal 오차 메타데이터를 붙인다. 표시용 소수 문자열을 정확값으로 오인하지 않는다.

기본 상한은 축전기 32개·노드와 이상적 제약 가지 합 256개·정수 4096 bit·GCD 나머지 500만 회·Jacobi 80 sweep·안정화 확장 256회/이분 탐색 80회다. 어댑터는 부품/도선 질의를 각각 1024개, 한 임의 전류 질의를 1024항으로 제한한다. 이 개수는 계산 성공 보장이 아니다. 16단 제품 회로는 통과했고 32단은 GCD 예산 초과로 거부됐다. FPS·경과 벽시계로 허용오차나 예산을 바꾸지 않는다.

회로 v7·측정 기록 v6는 변경하지 않는다. 새 도선 항과 plan/frame의 private 수치 정보는 실행 중 데이터이며 저장 스키마에 넣지 않는다. 실제 엔진 프레임의 시간·정확/근사 출처는 C1 기록 API로 저장할 수 있다. 기록 버튼의 잠금·일시정지 UX는 C3/C4다.

## 검증

[C2 결과](../docs/testing/rc-c2-results.md)에 실제 v7 컴파일, 독립 다중 RC 기준, 전하/에너지, 재조작·충격 거부, 도선 합과 고리, 결정성·변조 거부, 계산 예산 및 기존 DC 회귀를 기록한다. 실제 화면 연결과 브라우저 성능 수용 완료로 확대 해석하지 않는다.
