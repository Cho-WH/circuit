# ADR-006: Three.js 연동 방식

- 상태: accepted
- 결정 시점: 단계 3 전

## 질문

전위 높이 보기를 직접 Three.js로 구성할지, React 연동 계층을 사용할지 결정한다.

## 고정 조건

- 2D와 3D가 같은 `CircuitDocument`와 `SimulationResult`를 사용한다.
- 3D 모듈은 회로 계산을 수행하지 않는다.
- x-y 위치 대응과 선택 강조를 유지한다.
- 중급 태블릿에서 30 fps 이상을 목표로 한다.
- 움직임 감소와 2D 대체 표현을 지원한다.

## 평가 기준

- 2D 상태와의 동기화
- 렌더링 성능
- 테스트 가능성
- 카메라·선택 제어
- 장기 WebXR 확장 가능성

## 단계 3 구현 결정

React 컴포넌트 안에 직접 Three.js 어댑터를 둔다. 전위 모델은 문서 좌표 x/y와 이미 계산된 `z = scale × (V - V_reference)`를 넘긴다. 어댑터는 SVG 좌표를 `(x, -y, z)`로 변환하고 전기 계산을 수행하지 않는다. 2D 숫자·색상·3D 높이는 동일한 net 전위 객체에서 유도한다.

직교 카메라와 OrbitControls를 사용한다. 사선·정면은 Z-up, 위에서 보기는 +Z 방향과 Y-up으로 SVG의 오른쪽·아래쪽 대응을 보존한다. 카메라 변화·크기 변경·모델 변경 때만 그리며 연속 애니메이션을 사용하지 않는다. 제거 시 리스너·컨트롤·geometry·material·renderer를 해제한다.

정의되지 않은 전위와 열린 스위치의 연결 선은 생성하지 않는다. WebGL2 사용 실패 시 한국어 원인과 2D 경로 그래프 대안을 제공한다. 단계 3의 자동·브라우저 기능 검증을 통과했다. 실제 태블릿 성능 예산과 사용자 연구는 교실 알파에서 검증한다.


## MVP 후속: 기준면 회로도와 연속 전환

VIS-004/PV-01~04,07~08에 따라 3D 공개 입력을 `CircuitDocument`, 공통 `PotentialModel`, 선택·표시 상태로 확장한다. 저장 스키마 변경은 없다. 바닥 회로는 공통 SVG exporter로 생성한 투명 텍스처이며 2D와 같은 부품 기호·배선·라벨을 보존한다. 불투명한 판을 두지 않아 음의 전위가 0 V 아래에서도 보인다.

숫자 눈금, net당 하나의 전위 표지, 수직 투영 안내선, 선택 부품의 부호 있는 단자 전압 차이를 제공한다. 정의되지 않은 전위는 바닥에 남기며 높이를 부여하지 않는다. 열린 스위치의 단자는 표시하지만 그 사이 연결은 생성하지 않는다. 모든 표지는 카메라에 투영한 DOM이며 겹침과 뷰포트 이탈을 피한다.

리소스 준비가 끝난 첫 진입/새 문서 버전에서 1100ms의 유한한 높이·카메라 전환을 사용하며, 같은 문서 버전의 재진입은 900ms로 줄인다. `prefers-reduced-motion`이면 즉시 최종 장면을 표시한다. 전환 종료 뒤에는 기존처럼 변경 때만 렌더링한다. 언마운트·새 데이터·사용자 카메라 조작에서 프레임 요청을 취소하며 텍스처를 포함한 GPU 자원을 해제한다. 선택·숫자·색상·축척 변경 때 사용자의 카메라 방향을 유지한다. 경로 그래프는 3D에서 기본 접힘이며 별도 버튼으로 펼칠 수 있다.


### 2026-09-23 색상 범례와 화면 공간

visualization은 읽기 전용 `potentialColorStops`를 공개한다. `potentialColor`는 이 색상점을 보간하고 UI 범례는 같은 색상점에서 그라데이션을 생성한다. 전위 범위·계산·저장 계약은 바뀌지 않는다. 3D 제목과 축 이름 중복 표기를 제거하고 카메라 도구는 화면 위 오버레이로 배치한다. 기준 전위·높이 배율·축 눈금은 유지한다.


### 2026-09-24 준비 계약과 카메라 전환 (VIS-004, QLT-001)

app의 PotentialWorkspace가 2D → 준비 → 진입 → 완료/복구 가능한 실패를 관리한다. 준비 중에는 기존 2D DOM을 유지하고, potential-3d는 WebGL 생성·수학 글꼴·바닥 SVG 텍스처·장면 구성·첫 렌더를 모두 끝낸 뒤 onReady를 알린다. 입력 sourceView는 2D SVG viewBox이며 첫 직교 투영의 중심과 배율을 맞춘다. 진입은 1100ms, 준비한 동일 문서 객체의 재진입은 900ms다. onEntered는 전환 완료 또는 사용자 중단을 알린다. WebGL·글꼴·텍스처·컨텍스트 손실은 안정된 onError 코드로 구분하며, 앱은 12초 동안 준비가 완료되지 않는 경우에도 2D를 유지하고 다시 시도/2D 보기를 제공한다. 단순 준비 타이머는 성공 신호가 아니다.

문서 객체 교체와 모드 이탈은 준비 시도를 해제하고 늦은 import·이미지 완료 신호를 무시한다. 모듈 캐시와 WeakSet의 완료 이력만 유지하며, 2D 복귀 때 WebGL 리스너·프레임·OrbitControls·geometry·material·texture·renderer를 해제한다. 2D DOM은 3D 뒤에서 hidden/inert 상태로 남겨 화면 위치를 보존한다. 저장 스키마나 전위 계산 계약은 바뀌지 않는다.

카메라 프리셋은 현재 시점부터 700ms로 보간한다. 새 프리셋은 현재 보간 위치부터 다시 시작하고, 드래그·휠 조작은 즉시 보간을 중단해 현재 카메라를 넘겨받는다. 일반 프리셋은 확대 비율을 유지하고 보기 초기화만 확대도 복원한다. 움직임 감소 설정에서는 진입·프리셋의 중간 프레임을 생략한다. 높이 전환은 같은 net을 같은 비율로 이동시키며 숫자에는 최종 계산 전압만 표시한다.

기준점은 3D 하단에서 수학 표기로 표시한다. 부품 이름은 배경 없는 글자, 전위값은 작은 표지, 선택 전압차는 강조 표지로 구별한다. 도구·하단 정보·세로 축 주변은 표지의 충돌 회피 영역이다. 물리 전위 색상·눈금·음전위·열린 스위치의 연결 규칙은 그대로 유지한다.

검증은 potential-workspace.test.ts의 지연·취소·문서 교체·실패·재시도·무응답 제한·재진입과 potential-3d-lifecycle.test.ts의 글꼴/텍스처 순서·첫 렌더 정렬·사용자 중단·움직임 감소·GPU 해제를 포함한다. 렌더러 모킹 테스트는 실제 WebGL 성능이나 시각적 매끄러움을 입증하지 않으므로 실제 브라우저 검증을 별도로 수행한다.

### 2026-09-24 카메라 속도와 바닥 선명도 조정

사용자 검토 후 첫 진입 1100ms·재진입 900ms·시점 프리셋 700ms로 조정했다. 보간은 오버슈트 없는 smoothstep을 사용한다. 카메라 위치와 회전을 독립적으로 보간하지 않고, 회전·표적·거리로 위치를 유도하여 매 프레임 표적을 바라보게 한다. 전환 중 직접 조작과 움직임 감소 동작은 유지한다.

바닥 SVG의 viewBox는 보존하고 실제 래스터 크기를 먼저 지정한다. 목표는 문서 단위당 4px이며 기기의 최대 텍스처 크기·한 변 4096px·총 800만 픽셀 이내로 제한한다. 같은 크기의 CanvasTexture에 mipmap 선형 필터와 기기 지원 범위 내 최대 16배 이방성 필터를 사용해 사선에서의 세부 손실을 줄인다. 바닥 투명도와 물리 높이·색상·좌표는 바꾸지 않는다.

### 2026-09-24 높이 조절 시 라벨 수명과 위치

VIS-004: 축·net·부품·전압 차이 표지를 의미 ID로 유지하며, 높이와 표시 상태 변경에는 위치·내용만 갱신하고 사라진 표지만 제거한다. 화면 좌표는 매 렌더의 카메라 투영 결과를 CSS `translate`에 직접 적용한다. 전역 버튼의 `transform` 전환·눌림 효과는 표지에 적용하지 않아 장면과 표지 사이에 별도 위치 보간이 발생하지 않도록 한다. 새 표지는 첫 투영 전까지 숨기고, 장면 해제 때 모든 표지를 정리한다. 카메라·전위 계산·저장 형식은 유지한다.

개발 중 Fast Refresh는 이 컴포넌트의 상태를 보존하지 않고 장면을 재생성한다(`@refresh reset`). WebGL 렌더 콜백·명령형 DOM·React 상태가 서로 다른 코드 버전에 속하는 것을 막기 위해서다. 새 runtime은 오버레이를 비운 뒤 소유권을 가져오며, 일반 높이 변경에는 기존 라벨을 계속 재사용한다.
