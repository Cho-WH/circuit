# ADR-006: Three.js 연동 방식

- 상태: accepted
- 결정 시점: 단계 3 전

## 질문

전위 높이 보기를 직접 Three.js로 구성할지, React 연동 계층을 사용할지 결정한다.

## 고정 조건

- 2D와 3D가 같은 `CircuitDocument`와 `SimulationResult`를 사용한다.
- 3D 모듈은 회로 계산을 수행하지 않는다.
- x-y 위치 대응과 선택 강조를 유지한다.
- 중급 태블릿에서 30 fps 이상을 목표로 한다.
- 움직임 감소와 2D 대체 표현을 지원한다.

## 평가 기준

- 2D 상태와의 동기화
- 렌더링 성능
- 테스트 가능성
- 카메라·선택 제어
- 장기 WebXR 확장 가능성

## 단계 3 구현 결정

React 컴포넌트 안에 직접 Three.js 어댑터를 둔다. 전위 모델은 문서 좌표 x/y와 이미 계산된 `z = scale × (V - V_reference)`를 넘긴다. 어댑터는 SVG 좌표를 `(x, -y, z)`로 변환하고 전기 계산을 수행하지 않는다. 2D 숫자·색상·3D 높이는 동일한 net 전위 객체에서 유도한다.

직교 카메라와 OrbitControls를 사용한다. 사선·정면은 Z-up, 위에서 보기는 +Z 방향과 Y-up으로 SVG의 오른쪽·아래쪽 대응을 보존한다. 카메라 변화·크기 변경·모델 변경 때만 그리며 연속 애니메이션을 사용하지 않는다. 제거 시 리스너·컨트롤·geometry·material·renderer를 해제한다.

정의되지 않은 전위와 열린 스위치의 연결 선은 생성하지 않는다. WebGL2 사용 실패 시 한국어 원인과 2D 경로 그래프 대안을 제공한다. 단계 3의 자동·브라우저 기능 검증을 통과했다. 실제 태블릿 성능 예산과 사용자 연구는 교실 알파에서 검증한다.


## MVP 후속: 기준면 회로도와 연속 전환

VIS-004/PV-01~04,07~08에 따라 3D 공개 입력을 `CircuitDocument`, 공통 `PotentialModel`, 선택·표시 상태로 확장한다. 저장 스키마 변경은 없다. 바닥 회로는 공통 SVG exporter로 생성한 투명 텍스처이며 2D와 같은 부품 기호·배선·라벨을 보존한다. 불투명한 판을 두지 않아 음의 전위가 0 V 아래에서도 보인다.

숫자 눈금, net당 하나의 전위 표지, 수직 투영 안내선, 선택 부품의 부호 있는 단자 전압 차이를 제공한다. 정의되지 않은 전위는 바닥에 남기며 높이를 부여하지 않는다. 열린 스위치의 단자는 표시하지만 그 사이 연결은 생성하지 않는다. 모든 표지는 카메라에 투영한 DOM이며 겹침과 뷰포트 이탈을 피한다.

첫 진입/새 문서에서만 1.1초의 유한한 높이·카메라 전환을 사용한다. `prefers-reduced-motion`이면 즉시 최종 장면을 표시한다. 전환 종료 뒤에는 기존처럼 변경 때만 렌더링한다. 언마운트·새 데이터·카메라 버튼에서 프레임 요청을 취소하며 텍스처를 포함한 GPU 자원을 해제한다. 선택·숫자·색상·축척 변경 때 사용자의 카메라 방향을 유지한다. 경로 그래프는 3D에서 기본 접힘이며 별도 버튼으로 펼칠 수 있다.
