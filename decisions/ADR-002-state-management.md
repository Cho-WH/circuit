# ADR-002: 상태 관리 방식

- 상태: accepted
- 결정 시점: 단계 2 전

## 질문

문서 명령 기록, 실행 취소, 선택 상태, 드래그 미리보기, 자동 저장을 어떤 상태 관리 방식으로 구현할 것인가?

## 고정 조건

- `CircuitDocument`와 UI 상태를 분리한다.
- 문서 변경은 `Command`를 통한다.
- `ActivityPolicy`를 명령 실행 전에 검사한다.
- 실행 취소·다시 실행이 문서 의미를 보존한다.
- 핵심 도메인 모듈은 선택한 UI 상태 라이브러리를 알지 않는다.

## 비교할 대안

1. 경량 외부 상태 라이브러리 + 명령 기록
2. React 기본 상태 + 독립 문서 저장소
3. Redux 계열 명령·리듀서 구조

## 평가 기준

- 명령 기록과 스냅샷 비용
- 선택·드래그 같은 고빈도 UI 상태 분리
- 테스트 가능성
- 개발 복잡도
- 브라우저 개발 도구 지원

## 결정과 구현 계약

React 기본 상태와 순수한 문서 명령·스냅샷 기록을 사용한다. UI 선택·드래그·패널 상태는 문서 밖에 두며 모듈 구현 전 메인이 계약을 확정한다.

- `History`: `past`, `present`, `future` 문서 스냅샷. 최소 100회 실행 취소·다시 실행을 보존한다.
- `executeCommand(history, command)`: 명령 권한 검사→새 문서 작성→구조 검증 후 성공 상태 또는 구조화된 진단 반환. 실패 시 원래 history 유지.
- `undo(history)`, `redo(history)`: 원본을 변경하지 않는 기록 이동.
- 문서 명령은 부품 추가·복수 이동·회전·삭제·배선·속성·이름·기준점·분기점·주석·문서 교체를 포함한다.
- 복사는 부품·단자·포함 도선·분기점·주석에 새 ID를 부여한다. 선택 영역 밖의 전기 연결은 복사하지 않는다.
- 저장 모듈은 검증된 현재 버전 문서를 JSON으로 직렬화한다. 자동 저장본과 명시 저장본을 별도 키로 보존하고 손상된 파일은 현재 문서에 적용하지 않는다.

출력 표시 속성은 부품 `properties`, 주석 좌표·표기 속성, `output.fontScale`에 저장한다. 현재 저장 형식은 v4이며 이전 버전 변환은 ADR-012를 따른다. 단계 2에서 125회 실행 취소·다시 실행, 복사 ID 분리, 실패 명령의 원본 보존과 저장 복구 검증을 통과했다.


### 측정 UI 후속 분리

측정 도구 종류와 측정 가지 선택은 App의 일시 상태로 올려 캔버스 선택과 동기화한다. MeasurementPanel은 모드 전환에도 마운트를 유지하여 기록을 보존한다. CircuitCanvas의 `readOnly` 입력은 드래그·드롭·값 수정·스위치 더블클릭을 차단하고 단자 선택과 뷰 조작을 유지한다. App도 측정 모드의 편집 단축키를 차단하며 `dispatch`에서 문서 교체 이외의 편집 명령을 거부한다. 표시만 숨겨 문서 수정이 남는 상태를 피한다. 저장 스키마 변경은 없다.

### 드래그 미리보기와 명령의 일치 (EDT-001/002/005/006)

- `previewCommand(document, command)`는 권한 검사·문서 변환·검증을 수행하여 독립 문서 또는 구조화된 진단을 반환한다. 원본·기록·저장 상태는 변경하지 않는다. `executeCommand`는 이 함수를 호출한 뒤 성공 결과만 기록한다.
- 캔버스는 이동 미리보기 문서를 직접 조립하지 않는다. `MoveComponents`를 같은 공개 함수에 전달한다. 실제 위치가 바뀐 단자에 연결된 도선만 ADR-016의 국소 보정 규칙을 적용하고, 나머지 도선의 꺾임 좌표와 연결 ID는 보존한다. 연결된 도선의 waypoints를 모두 지우던 정책은 ADR-016으로 대체한다.
- 같은 위치로의 이동은 도선 경로와 undo/redo 기록을 변경하지 않는다.
- 드래그는 시작 문서·시작 좌표·현재 좌표·선택 위치·포인터 ID를 하나의 세션으로 유지한다. 놓는 이벤트의 좌표로 최종 명령을 만든다. Escape, pointercancel, 캡처 손실, 창 초점 이탈, 문서/도구/편집 권한 변경 시 세션을 폐기한다. 다른 포인터는 진행 중인 세션을 수정하거나 확정하지 못한다.
- 실제 React 이벤트와 SVG points를 검증하는 happy-dom 회귀 테스트를 추가한다. SVG 화면 좌표 변환은 테스트에서 고정하고 실제 브라우저에서 확대 상태와 포인터 배치를 확인한다. 저장 형식과 물리 모델은 바뀌지 않는다.

### 문맥 배선과 원자적 명령 묶음 (EDT-002/003/005)

`executeCommands(history, readonly Command[])`를 editor 공개 API에 추가한다. 각 명령을 순서대로 `previewCommand`에 전달하여 권한·구조를 검사하고 모두 성공한 최종 문서만 한 번의 기록으로 저장한다. 중간 실패와 빈 목록은 부분 문서를 게시하지 않는다. 별도의 우회 권한이나 저장 스키마는 추가하지 않는다.

배선 중 도선 위 시작점은 UI의 임시 WireAnchor이며 실제 Junction을 저장하지 않는다. 완료 시 AddJunction과 ConnectWire/ConnectToWire를 묶어 실행한다. AddJunction의 도선 분할도 공통 splitWire를 사용하여 기존 꺾임과 외부 단자를 보존하고 도선 내부가 아닌 좌표를 거부한다.

`app/wiring`의 model은 대상 판정과 명령 구성을, useContextWiring은 배선 시작·후보·터치 확인·교차 안내의 수명을, WiringOverlay는 표시를 담당한다. useTouchNavigation은 이동·핀치·후속 클릭 억제만 담당하며 회로 명령을 실행하지 않는다. App은 문서 기록과 모드 권한 검사를 소유하고 Canvas는 이벤트와 각 모듈을 연결한다.

## 회로 위 이름·값 편집

회로 위 편집창은 이름·값 초안을 함께 유지한다. 적용 시 바뀐 SetLabel·SetProperties를 executeCommands로 검증하여 하나의 기록으로 발행한다. 값이 없거나 변경되지 않으면 해당 명령을 생략한다. 권한 검사 실패는 부분 적용하지 않으며 Escape는 두 초안을 모두 취소한다. 표시 이름은 ID 연결을 변경하지 않는다.

## 화면 상태와 파일 작업 분리 (2026-09-24)

2D viewBox는 문서 ID와 함께 App의 일시 상태로 보존해 만들기·전위·측정 전환에서 같은 시야로 돌아간다. 출력 전용 주석 선택은 회로 편집으로 전환할 때 제외한다. 파일 다운로드는 수동 보관본을 변경하지 않으며 FileMenu의 명시적인 보관 동작만 manual 키를 갱신한다. 보관본 불러오기는 기존 ReplaceDocument와 실행 취소를 사용한다. 자동 저장·보관·계산·측정 기록의 저장 범위와 v4 스키마는 유지한다.

### 화면 구현의 책임 분리 (2026-09-24)

App 내부 `useCircuitSession`이 문서 이력·화면 모드 제한·명령 실행·450ms 자동 저장을 소유한다. 단일 명령과 묶음 명령 모두 같은 모드 검사 경로를 지나 editor에 전달한다. 같은 이벤트에서 연속 명령을 실행해도 마지막 확정 이력을 사용한다. 첫 전원 배치와 허용된 자동 기준점 지정은 기존과 같이 한 undo 단위이며, 활동이 SetReference만 거절하면 전원 배치 자체는 유지한다.

Canvas의 드래그 세션·포인터 캡처·미리보기는 `useCanvasDragSession`, 입력 초안·파싱·초점은 `InlineComponentEditor`로 나눈다. Canvas는 모드·문서·도구 변경과 Escape/취소/캡처 손실/초점 이탈을 기존과 같이 조율한다. React 기본 상태, editor의 공개 명령, 문서 v4와 물리 계산 정책은 유지한다. 새 전역 상태 계층은 추가하지 않는다.

## 터치 입력 수명과 화면 크기 변화 (2026-09-24)

사용자가 수정한 터치 점검 보고서를 기반으로 EDT-001/004/005, VIS-004, TCH-001의 입력 계약을 보완한다. `useTouchNavigation`은 포인터 집합·450ms 대기·10 CSS px 이동 임계값·핀치·후속 클릭 억제를 소유하고 명령은 실행하지 않는다. 첫 번째 새 pointerdown에서 억제를 해제하므로 다중 터치의 연속 click은 차단하되 다음 터치와 마우스 입력은 정상 처리한다.

선택되지 않은 대상은 길게 누른 뒤 이동하며 선택된 대상/손잡이는 즉시 이동한다. 두 번째 손가락은 부품·측정·출력의 편집 세션을 먼저 취소한다. 측정 핸들도 부모 캔버스의 포인터 집합에 등록한다. 취소·캡처 손실·초점 이탈·Escape·문서/도구 변경·화면 크기 변화는 원본과 이력을 보존한다. 라이브러리 세션은 부품 선택과 화면 좌표만 전달하며 네이티브 HTML 드래그에 의존하지 않는다. 모드 변경/배치 완료 시 전달 이벤트도 폐기해 재마운트로 배치를 재실행하지 않는다.

`useCanvasViewport`는 이전 실제 캔버스 크기와 viewBox로 화면 배율을 계산하여 다음 크기에도 유지한다. 선택/편집 대상의 가시성에 필요한 만큼만 시야를 이동한다. 세로 편집 영역 축소로 자동 이동한 중심은 확장 시 복구하되 그 사이 사용자가 이동·확대했다면 복구하지 않는다. 방향 전환은 현재 중심·배율을 기준으로 다시 계산한다. `useVisibleViewport`는 브라우저 페이지 확대와 앱 확대를 구분하면서 실제 보이는 높이를 CSS에 전달한다. 입력 초안·선택과 문서 좌표는 변경하지 않는다.

새 공개 editor 명령·저장 필드·마이그레이션은 없다. 이동/삽입/출력 위치 조절은 기존 명령과 원자적 이력을 사용한다. 이벤트 검사는 `tests/touch-interactions.test.ts`, 3D 선택 검사는 `tests/potential-3d-lifecycle.test.ts`에서 수행한다. 실제 모바일 브라우저의 키보드·스크롤·취소 이벤트 순서는 별도 실기기 검증 대상이다.
