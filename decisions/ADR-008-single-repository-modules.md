# ADR-008: 단일 저장소와 모듈 경계

- 상태: accepted
- 결정일: 2026-09-23

## 배경

초기부터 여러 패키지와 플러그인 체계를 만들면 개발 비용이 커지고 실제 경계가 검증되지 않은 상태에서 구조가 고정될 수 있다.

## 결정

초기에는 하나의 저장소와 하나의 앱 안에서 모듈 폴더 경계를 지킨다. 안정된 `domain`과 `simulation`만 재사용 필요가 확인된 뒤 독립 패키지로 분리한다.

## 결과

- import 규칙으로 의존 방향을 검사한다.
- 모듈 내부 파일은 공개하지 않고 `index`를 통해 필요한 API만 노출한다.
- 외부 플러그인 설치 기능은 MVP에서 만들지 않는다.
- 패키지 분리는 실제 두 번째 소비자가 생겼을 때 검토한다.

## 내부 의존 검증 보완 (2026-09-24)

모듈 간 경계 외에 같은 모듈 안의 런타임 파일 순환도 검사한다. TypeScript 구문으로 import·re-export·동적 import·require를 읽으며 주석과 지워지는 type-only 참조는 런타임 순환에서 제외한다. 타입 참조도 기존 모듈 경계 규칙은 지킨다. simulation의 해석 구현은 내부 solver 파일에 두고 측정 함수는 이를 직접 사용한다. 공개 index는 외부 소비자를 위한 진입점이며 내부에서 역참조하지 않는다. 기존 공개 함수·저장 형식은 유지한다.
