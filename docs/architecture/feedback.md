# 사용 후기와 피드백

요구사항 DAT-005, 결정 [ADR-014](../../decisions/ADR-014-feedback-board.md).

## 현재 구성

`app/FeedbackBoard` → `feedback` 공개 계약 ← `feedback-local`.

앱 상단의 한마디 버튼이 네이티브 모달을 연다. 본문 세 줄 미리보기와 더 읽기, 종류 배지, 닉네임, 작성일을 사용한다. 제목·별점·회원 가입은 없다. 공개 목록, 같은 브라우저의 본인 글, 개발 환경의 관리자 보관함을 구분한다. 비공개 글을 작성하면 본인 목록으로 이동한다.

현재 연결 지점은 `FeedbackFeature`의 `createBrowserFeedbackPreview()`다. `FeedbackBoard`는 `gateway`와 선택적인 `admin`만 받고 저장소에 직접 접근하지 않는다. 미리보기 데이터는 `circuit.feedback.preview.v1`에 보관되며 익명 식별자를 자동 생성한다. 브라우저 데이터 초기화는 익명 ID와 미리보기 데이터도 지운다. 운영 데이터 마이그레이션이나 실제 교사 후기 배포는 이번 범위에 포함하지 않는다.

## 원격 연결 시 준수할 계약

1. Firebase 익명 인증은 어댑터에서 자동 수행한다. 클라이언트가 제공하는 ownerId나 관리자 여부는 신뢰하지 않는다.
2. 공개 읽기 자료와 서버 전용 원문·비밀번호 검증 자료를 분리한다. Firestore 문서 읽기는 필드 단위 비밀 보장을 대신할 수 없으므로 해시를 공개 문서에 넣지 않는다.
3. 신뢰할 수 있는 서버 명령이 인증 토큰을 검증하고 서버 시각의 한국 날짜와 UID를 키로 사용하여 할당량 검사·증가·글 저장을 한 트랜잭션에서 실행한다. 삭제해도 카운터는 줄이지 않는다.
4. 공개 목록은 `visibility=public`, `deletedAt=null`만 읽는다. 본인 글은 인증 UID로 제한한다. 각 목록은 20개 단위로 반환한다. 삭제된 커서 항목 때문에 다음 페이지를 놓치지 않는 안정된 커서를 사용한다.
5. 비밀번호 검증과 소프트 삭제는 서버에서 수행한다. 검증 시도 제한, 입력 검증, 원문 보관과 공개 자료 제거를 보장한다. 비밀번호는 URL·로그·인증 클레임에 넣지 않는다.
6. `FeedbackAdminGateway.list`는 모든 요청에서 검증된 관리자 권한을 확인하며 원문·공개 범위·삭제 시각을 반환한다. 일반 UI의 탭 숨김을 권한 검사로 간주하지 않는다.
7. 네트워크 또는 인증 실패는 `FeedbackResult` 코드로 매핑한다. UI에는 SDK 예외를 노출하지 않는다. 로컬 미리보기 안내는 실제 원격 연결 상태에 맞게 교체한다.

Firebase SDK/인증 제공자/Firestore 보안 규칙/서버 명령 배포 및 요금제 결정은 아직 수행하지 않았다. 직접 Firestore 클라이언트 쓰기만 붙이는 것으로 관리 비밀번호 계약을 충족했다고 판단하지 않는다.

## 검증

- `tests/feedback.test.ts`: DTO 분리, 비공개 접근, 비밀번호·해시, 동시 요청, 날짜 경계, 소프트 삭제, 실패 보존, 페이지네이션.
- `tests/feedback-ui.test.ts`: 작성/삭제 통합, 실패 시 입력 보존, 관리자 삭제 표시, 조회 오류.
- 실제 브라우저: 작성·공개 범위·삭제·재열기·좁은 화면·키보드 동선.
