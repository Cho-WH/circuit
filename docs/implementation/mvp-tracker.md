# 작업과 검증 기록

현재 범위는 [현황](current-phase.md), 규칙은 요구사항·ADR·물리 문서, 실행 근거는 [검증 범위](../testing/mvp-coverage.md), 미완료 항목은 [남은 작업](follow-up.md)을 따른다. 새 기록은 변경 결과·회귀 방지 이유·실제 검증·미완료만 남긴다. 중간 대화·역할 분담·반복 테스트 수·커밋 대기 상태는 누적하지 않는다.

## 2026-09-24 구조 정리와 화면 책임 분리

- QLT-003, SIM-002, EDT-001/002/004/005, DAT-001, VIS-007: simulation 해석기를 내부 solver로 이동해 index↔measurements 순환을 제거했다. 기존 공개 API·물리 계산·문서 v4는 유지한다. 경계 검사는 TypeScript 구문을 읽고 모듈 내부 런타임 순환도 잡으며, 주석과 type-only 참조를 구분한다.
- `useCircuitSession`에 문서 이력·화면 모드 검사·단일/묶음 명령·자동 저장을 모았다. `useCanvasDragSession`에 이동 세션·캡처·미리보기를, `InlineComponentEditor`에 입력 초안·오류·초점을, `PotentialSettings`에 전위 설정 표시를 분리했다. Prettier를 개발 의존성으로 추가하고 변경 파일에만 적용했다. 새 전역 상태 계층이나 독립 기능 패키지는 추가하지 않았다.
- 구조도와 처리 흐름을 현재 코드에 맞췄다. 위치·라벨 변경도 현재는 전체 재계산하며, ActivityPolicy·범용 부품 등록 예시는 미구현 확장 방향으로 구분했다. 3D 내부 분리는 다음 장면 변경 때 검토하도록 남은 작업에 기록했다.
- 최종 일반 테스트 29개 파일 540개, 타입·경계(69개 소스)·프로덕션 빌드·명세·변경 파일 포맷·공백 검사를 통과했다. 새 회귀는 연속 명령, 묶음 실패 시 원본 보존, 화면 모드 제한, 첫 전원과 기준점의 한 번 undo, 자동 저장과 수동 보관 분리, 내부 순환 import를 검증한다. Firestore 전용 24개는 제외되었고 기존 큰 청크 경고는 남는다.
- 메인이 별도 127.0.0.1:5184 빌드 미리보기에서 이름·값 동시 변경/undo/redo, 부품·도선 선분 이동과 points의 정확한 undo 복원, 전위 범위·높이 변경과 3D 진입, 6 V 탐침 측정, 출력 설정과 편집 복귀, 새로고침 후 자동 저장 복구를 확인했다. 390×844에서 입력을 시작하고 844×390으로 바꿔 이름·값 초안 유지와 입력창 배치를 확인했다. 콘솔 오류는 없었으며 실제 모바일 하드웨어 검증은 아니다. 작업 시작 시 존재하던 ComponentPalette·touch-interactions 변경 파일의 해시는 보존했다.

완료된 UX 검토 3종·옛 화면 캡처·중간 실행 로그를 제거하고 현황·검증·운영 문서를 압축했다. 향후 단계와 유보 후보는 남은 작업에, 학생·교사·실기기 수용 과제는 사용성 문서에 보존했다. 색상 비교용 임시 웹앱과 전용 자료·로그·초기 후보 캡처도 삭제했다. 정식 팔레트·회귀 테스트·요구사항·ADR·스키마·fixture·기능 코드는 유지한다. 로컬 링크 111개·앵커·명세·공백 검사를 통과했고, 원문의 UX·터치 수용 과제 보존과 삭제 자료 참조 0건을 확인했다. 코드 테스트·빌드는 반복하지 않았다.

## 2026-09-24 도선 경로 편집과 부품 삭제 — ADR-016/017

- EDT-001/002/003/005, SIM-001: 빈 곳 클릭·탭으로 경유 구간을 만들고 방향 전환·마지막 경유점 되돌리기를 제공한다. 선택 도선의 사각 손잡이로 선분을 수직 이동한다. 부품 이동·회전은 인접 코너만 조정하고 가운데 경로·다른 가지를 보존하며 양 끝 변위가 같으면 전체를 평행 이동한다.
- 순수 `wire-geometry`, 문서 명령 `editor`, 임시 조작 `app/wiring`을 분리하고 모듈 경계를 검사한다. 시작 문서와 최종 변위로 같은 명령을 미리보기·확정에 사용한다. 기존 waypoints·v4 저장 형식을 유지한다. 규칙과 공개 명령은 [ADR-016](../../decisions/ADR-016-local-wire-routing.md)에 기록했다.
- 연결된 두 단자 부품 삭제는 부품 자리를 도선으로 잇고, 삭제로 만든 앵커 없는 두 도선 접점은 합친다. 직렬 구간에 새 노드를 남기지 않으며 굴곡·되접힘·실제 분기·열린 끝·기준점·주석을 보존한다. 명시적으로 선택한 도선·분기점 삭제가 우선하며 고립 부품은 흔적 없이 제거한다.
- 삭제 연결 정책은 `editor/delete-elements.ts`, 접점 정리는 `editor/wire-edits.ts`, ID 예약은 문맥 배선과 공유하는 domain 함수로 분리했다. UI는 기존 DeleteElements를 사용한다. 미지원 세·네 단자 입력은 서로 다른 단자를 연결하지 않고 같은 단자의 외부 배선만 정리한다. 트랜지스터·정류기 모델은 후속 범위다. 세부 규칙은 [ADR-017](../../decisions/ADR-017-delete-components-keep-wiring.md)을 따른다.
- 최종 전체 28개 파일 530개 테스트·타입·경계(64개 소스)·Vite 빌드·공백 검사 통과. 기존 물리 fixture, 직각성·경로 보존·입력 불변·권한·저장 왕복·undo/redo, 혼합/동시 삭제, ID 충돌, 다단자 net 분리와 폐곡선, 직렬 삽입 후 삭제 시 경로·전류 복원을 확인했다. Firestore 전용 24개는 제외되었고 기존 큰 청크 안내는 남는다.
- 최종 문서 정리 후 specifications 테스트 74개와 저장소 `.venv`의 `tools/validate_specs.py` 명세 검사를 통과했다.
- 메인 브라우저에서 부품 이동·선분 드래그·경유점 배선·저장 재열기·SVG/PNG 출력, 390×844 도구 배치·키보드 조작을 확인했다. 삭제 버튼/Delete 키·단락 진단을 확인했고, 최종 직렬 예제 삭제는 새 노드 없이 경로를 합치며 실행 취소 시 points를 정확히 복원했다. 콘솔 오류는 없었다. 실제 모바일 기기의 터치 수용 검증은 남아 있다.
