# 과부하·파손 설명 물음표 설계

- 작성일: 2026-10-06
- 상태: **accepted — 사용자 승인 후 H01~H07 로컬 구현 완료**
- 대상: 고등학생이 분석 화면의 예상 밖 결과를 보고 이유를 찾아보는 경험
- 이번 산출물: 표시 위치·등장 조건·학생용 문구·예외 처리·모듈 경계·수용 기준

이 문서는 기존 과부하·파손 판정, 값 변경 잠금, 초기화 동작을 유지하면서 부품의 물리적 이유를 설명하는 구현 계약이다. H08~H10은 사용자 요청으로 제외했다. 회로 v6·측정 기록 v5와 계산 모델은 유지한다. [ADR-026](../../decisions/ADR-026-diode-boundary-analysis.md), [작동 경계](../physics/circuit-operating-boundaries.md), [분석 UX](diode-analysis.md)를 따르며, 짧은 경고와 선택형 설명을 구별한다. 구현·검증 근거는 [작업 기록](../implementation/mvp-tracker.md)에 남긴다.

## 1. 학생에게 전달할 핵심

학생은 평소 이상적인 회로로 관계를 익히고, 지나친 조건에서는 평소 생략했던 부품의 성질을 관찰한다. 물음표는 그 차이가 보이는 곳에서 이유를 짧게 설명한다.

설명 대상은 **회로와 부품의 물리적 현상**으로 한정한다. 값 변경 제한, 초기화 방법, 측정 중단, ≈ 표기 등 앱 조작·표시에 대한 질문은 추가하지 않는다.

1. 전지 내부저항은 과부하가 생겼을 때 새로 생기는 성질이 아니다. 단자전압의 하강만으로 전지가 영구 손상됐다고 판단하지 않는다.
2. 다이오드의 0.7 V는 수업에서 쓰는 단순화다. 현재의 전압·전류와 모순되는 절대 규칙으로 설명하지 않는다.
3. 과부하는 감당할 조건을 벗어났다는 뜻이며 파손과 구별한다.
4. 발열의 물리적 이유는 설명하되 현재 온도, 실제 고장 시간, 열 축적을 계산한 것처럼 말하지 않는다.

관련 원칙은 P-04 정보 절제, P-05 교육적 정확성, P-06 오류에서 학습, P-08 확장 경계다. 관련 요구사항은 EDT-008, SIM-008, VIS-004/006/007, MEA-001/002/003, DAT-001~004다. 설명 표시는 기존 VIS-007에 반영한다.

## 2. 화면에서의 기본 형태

### 물음표와 경고의 역할

- 느낌표는 **어디에 문제가 생겼는지**, 물음표는 **왜 이런 현상이 보이는지**를 맡는다. 원인 하나에 느낌표·물음표·긴 설명 상자를 여러 개 띄우지 않는다.
- 관련 부품 이름 오른쪽 위에 작은 원형 `?`를 둔다. 부품 기호·단자·값·탐침·손상 표식 위에 겹치지 않는다. 시각적 지름은 약 18~20px, 실제 누를 영역은 44×44px로 확보한다.
- 물음표 원은 이름에서 기본 4px 간격에 두고, 투명한 클릭 영역은 바깥쪽·위쪽으로 확장한다. 손상 표식과 충돌하면 가까운 8px 위쪽 위치부터 확인해 물음표만 멀리 떨어지는 배치를 피한다. 충돌 검사는 전체 44×44px 영역을 유지한다.
- 기본 색상은 기존 회색·녹색 계열이다. 위험 색은 느낌표와 손상 표식, 초기화 버튼에 맡긴다. 물음표는 깜박이거나 자동으로 열리지 않는다.
- 클릭·탭·Enter·Space로 열고, 같은 버튼·닫기·Escape·바깥 클릭으로 닫는다. 본문은 마우스를 올려야만 볼 수 있는 형태로 만들지 않는다.
- 제목은 학생이 가질 질문 한 문장, 본문은 보통 2~3문장이다. 전지 설명처럼 필요한 경우 최대 4문장을 허용한다. 기본 본문에는 수식·정격표·내부 코드·모델 이름을 넣지 않는다.
- 부품의 물리적 이유만 설명하고 앱 조작·복구 절차를 붙이지 않는다. 경고·초기화 버튼이나 측정값 옆에는 설명 물음표를 추가하지 않는다.

### 문구의 기준 톤 — 사용자 지정

학생에게는 **눈앞의 현상 → 물리적 이유 → 지금 화면의 의미** 순서로 말한다. `내부저항`, `단자전압`, `역전압`처럼 수업에 필요한 말은 풀어서 쓰되, `모델 전환`, `임계값`, `프로필`, `판정 결과`, `세션`, `입력 잠금` 같은 개발 용어를 본문에 넣지 않는다. 과부하·파손 설명마다 “이 실험에서 정한 기준을 넘었어요”를 반복하지 않는다. 실제 부품과 화면의 차이는 해당 물리 현상을 오해하지 않는 데 필요한 범위에서만 설명한다.

아래 H01은 사용자가 제시한 문구를 기준으로 한다. 다른 문구도 설명서를 읽히는 말투보다 옆에서 현상을 짚어 주는 말투를 유지한다. `전류가 흐르면`, `양끝에서 재면`, `지금은 ... 보여주고 있어요`처럼 쓴다.

### 부품 옆에만 배치

| 위치 | 설명 대상 | 배치 |
|---|---|---|
| 부품 옆 | 전지 단자전압, 다이오드 전압, 해당 부품의 전류·전력·역전압 부담 | 기존 부품 라벨을 기준으로 배치. 한 부품당 `?` 한 개 |

```text
분석 화면 상단   [⚠] [회로 수정하기]

회로 위          V₁ [?]                 D₁ [?]
                  전지                  다이오드

측정 영역        ≈ 1.36 V
```

한 번에 설명 팝업은 하나만 연다. 부품당 기본 설명 하나만 먼저 보이며, 같은 부품에 실제로 다른 질문이 함께 있으면 `함께 궁금할 수 있어요` 아래 짧은 질문 버튼 최대 두 개로 같은 팝업의 내용을 교체한다. 중첩 팝업이나 전체 도움말 목차를 만들지 않는다. 대체 질문으로 이동해도 해당 부품에 묶인 같은 팝업이며 `돌아가기`로 첫 질문으로 복귀한다.

## 3. 상태별 등장 범위

| 현재 상태 | 부품 물음표 |
|---|---|
| 만들기 | 추가하지 않음. 기존 사전 경고 유지 |
| 정상·교과서 계산 | 추가하지 않음 |
| 정상·부품 성질을 반영한 계산 | 선택하거나 직접 측정 중인 전지·다이오드의 관련 설명만 |
| 과부하 | 위험 부품과 관련된 전지·다이오드의 설명 후보 생성 |
| 파손 연출 중 | 새 물음표의 진입은 연출 종료 후. 기존 열림은 닫음 |
| 파손 완료 | 파손 부품의 확인된 원인 설명만. 손상되지 않은 부품에 파손 설명을 붙이지 않음 |
| 초기화·새 회로·불러오기·분석 종료 | 모든 현재 설명·열림 상태를 정리 |

정상인데 부품 성질이 반영되는 경우도 있다. 교과서 계산이 정상 상한을 넘지만 부품 특성을 반영하면 정상인 조건, 명시적 부품 특성, 이상 해가 유일하지 않은 연결 등이 해당한다. 이때에도 필요한 설명을 선택 시 제공하되 과부하라고 말하지 않는다. 물음표가 있다는 사실 자체도 위험 판정이 아니다.

과부하 상태는 이미 마지막 값으로 고정되므로 설명을 여는 행위는 재계산·시간 진행·추가 파손을 만들지 않는다. 최초 분석부터 과부하라면 과거 화면을 보았다고 가정하는 `갑자기 바뀌었어요` 같은 문구를 쓰지 않는다.

## 4. 설명 후보를 고르는 규칙

### 공통 조건

- 현재 분석의 확정 문서·세션·결과만 사용한다. 과거 측정표, 화면의 반올림 문자열, 애니메이션 프레임에서 원인을 추정하지 않는다.
- 부품 성질 설명은 `result.provenance.physicalModel === 'component'`일 때만 후보가 된다. 위험 설명은 세션의 `OperatingAssessment.components`에 있는 확인된 원인만 사용한다.
- 부품별 원인이 여러 개면 기존 `OperatingAssessment` 순서를 사용한다. UI에서 위험 우선순위·경계값을 다시 만들지 않는다.
- 숫자의 존재, 부호와 비교 방향을 확인할 수 없으면 방향을 단정하는 문구를 생략한다. 공개 질의 결과와 `rational.direction`의 불확실성 판정을 재사용한다.
- 전압은 전원의 +→−, 다이오드의 A→K라는 단자 역할로 판단한다. 회전, 화면 좌우, 탐침의 빨강·검정 순서를 근거로 물리적 방향을 정하지 않는다.
- 설명 본문은 첫 버전에서 동적 전류·전력·임계 숫자를 삽입하지 않는다. 이미 있는 계기와 중복 표시하거나 반올림 때문에 다른 숫자를 설명하는 문제를 피한다.

### 부품별 조건

| 설명 ID | 후보를 만드는 근거 | 붙이지 않는 경우 |
|---|---|---|
| `source-terminal-drop` | 부품 계산, 전원 기전력 E > 0, 공급 방향 전류 > 0과 +→− 단자전압 < E가 모두 확인됨 | 전원 전류 0, 흡수 방향, 방향 불확실, 현재 측정 중단 |
| `source-terminal-rise` | 부품 계산, E > 0, 전류가 전원 +극으로 들어오는 방향과 단자전압 > E가 모두 확인됨 | 정상 공급, 0, 부호 불확실. 이를 충전·역전류 파손 판정으로 승격하지 않음 |
| `source-terminal-general` | 부품 계산의 전원을 직접 선택/측정했으나 E ≤ 0 등으로 위 두 문구가 맞지 않고 전압·전류가 확인됨 | 계산 불가. 자동으로 전압 하강 후보 대신 사용하지 않음 |
| `source-stress` | 해당 전원의 `sourceCurrent` 또는 `internalPower` 원인 | 다른 부품만 위험한 전원. 단자전압 하강만으로 발열 위험·파손이라 말하지 않음 |
| `diode-forward-voltage` | 부품 계산, A→K 전류 > 0이 확인된 다이오드 | OFF, 정확한 0 A, 역방향, 전류 미정 |
| `diode-forward-stress` | 해당 다이오드의 `forwardCurrent` 또는 `power` 원인 | 역전압만 원인인 경우 |
| `diode-reverse-stress` | 해당 다이오드의 `reverseVoltage` 원인 | 0 A라는 사실만으로 추정하지 않음 |
| `resistor-power` | 일반 저항·가변저항의 `power` 원인 | 큰 저항값·작은 저항값이라는 이유만으로 추정하지 않음 |

교과서 기준 강하가 0.7 V가 아닌 명시적 특성을 가진 다이오드에는 §5의 일반형 문구를 쓴다. 프로필 수치나 전원 내부저항을 도움말 쪽에서 다시 기본값으로 가정하지 않는다.

### 어떤 물음표를 먼저 보여줄 것인가

1. 과부하에서 부품 자체에 위험 원인이 있으면 그 원인을 기본 질문으로 삼는다. 전지의 단자전압, 다이오드의 기준 전압은 관련 질문으로 연결한다. 전지 자체가 정상이어도 그 전지에 확정된 단자전압 하강이 있으면 별도 설명 후보가 된다.
2. 부품 물음표는 자동 노출 최대 **3개**다. 우선순위는 현재 선택/직접 측정 부품 → 대표 위험 부품 → 전압 차이를 설명할 전원 → 나머지 위험 부품 → 나머지 부품 성질 순이다. 중복 부품은 하나로 합치고 동순위는 기존 안정된 부품 ID 순서를 쓴다. 화면 좌표는 우선순위의 근거가 아니다.
3. 별도 연결 회로에 생긴 과부하 때문에 무관한 전원의 물음표까지 자동으로 늘리지 않는다. 원인 부품과 같은 연결 성분에 속한 전원·다이오드만 자동 노출 대상이다. 기존 컴파일 연결 정보를 사용한다. 연결 관련성을 확인할 정보가 부족하면 원인 부품만 자동 표시하고 나머지는 선택 시 제공한다.
4. 3개를 넘거나 가려진 부품도 선택하면 해당 부품의 물음표가 첫 순위가 된다. 화면상의 표시만 줄이고 설명 후보를 삭제하지 않는다. 숨겨진/화면 밖 물음표를 Tab 순서에 남기지 않는다.

## 5. 학생용 문구

아래 인용문이 실제 학생용 본문이다. ID, 등장 규칙, 검수 주의점은 개발 문서에만 남긴다. 제목의 부품 이름은 회로에 표시된 이름으로 보완할 수 있다.

### H01. 전지 — 전지 전압이 왜 낮아졌나요?

> 전지 안에도 '내부저항'이 있어요. 전류가 작을 때는 그 영향을 무시할 수 있지만, 전류가 많이 흐르면 전지 양끝에서 측정하는 전압이 낮아지고 내부에서 열도 더 많이 발생해요.
>
> 지금은 이 영향을 포함한 전압을 보여주고 있어요.

관련 질문: **전지가 망가진 건가요?**

> 전압이 낮아졌다고 해서 전지가 망가진 것은 아니에요. 전류가 흐르는 동안 내부저항 때문에 양끝의 전압이 낮아질 수 있어요. 이것은 전지가 영구적으로 손상된 것과는 달라요.

`source-terminal-drop`은 전지 자신의 위험 원인이 없어도 등장할 수 있다. 이 경우 `전류가 과도해요`, `전지가 뜨거워졌어요`라고 현재 상태를 단정하지 않는다. 위 문구는 실제 전지에서의 일반적 발열 원리를 설명하며 앱이 온도를 계산했다는 뜻이 아니다. 정상 부품 계산에서도 같은 본문을 재사용한다.

### H02. 전지 — 전지 전압이 왜 더 높게 나오나요?

> 다른 전원이 이 전지 쪽으로 전류를 밀어 넣고 있어요. 전류가 반대로 흐르면 내부저항에 걸리는 전압의 방향도 바뀌어, 전지 양끝에서 재는 전압이 더 높아질 수 있어요. 그렇다고 모든 전지를 이렇게 충전할 수 있는 것은 아니에요.

흡수 방향이 확인된 경우에만 사용한다. 내장 프로필에 없는 역전류 위험 판정이나 충전 상태를 만들지 않는다.

일반형 질문: **전지 옆 숫자와 측정값은 무엇이 다른가요?**

> 전지 옆 숫자는 전류가 흐르지 않을 때의 전압을 나타내요. 탐침은 지금 전지 양끝의 전압을 재고 있어요. 전류가 흐르면 내부저항의 영향으로 두 값이 달라질 수 있어요.

### H03. 전지 — 왜 이 전지에 과부하가 걸렸나요?

> 전지가 감당하기 어려울 만큼 많은 전류가 흐르고 있어요. 전지 안에도 저항이 있어서, 전류가 많이 흐를수록 내부에서 열이 더 많이 나요. 지금은 전지에 무리가 가는 상태를 보여주고 있어요.

`sourceCurrent`의 과부하 문구다. `internalPower`만 원인이면 다음 본문으로 바꾼다. 흡수 방향 전류에도 맞는 표현이다.

> 전지 안에도 저항이 있어서, 전류가 흐르면 전기 에너지의 일부가 열로 바뀌어요. 지금은 그 양이 너무 커서 전지에 무리가 가고 있어요.

파손형 질문: **왜 이 전지가 손상된 모습인가요?**

> 전지에 너무 많은 전류가 흐르면 내부에서 열이 많이 나고 손상될 수 있어요. 지금은 전지가 감당하기 어려운 상태여서 손상된 모습으로 보여주고 있어요.

내부손실만 원인이면 첫 문장을 **“전지 내부에서 너무 많은 에너지가 열로 바뀌면 전지가 손상될 수 있어요.”**로 바꾼다. 발열의 원리를 설명하며 계산하지 않은 현재 온도나 고장 시간을 단정하지 않는다.

### H04. 다이오드 — 다이오드 전압은 항상 0.7 V 아닌가요?

> 수업에서는 다이오드에 전류가 흐를 때 양끝의 전압을 0.7 V로 놓고 살펴보곤 해요. 실제로는 흐르는 전류의 양에 따라 이 전압도 달라져요.
>
> 지금은 전류가 많아지면 다이오드 양끝의 전압도 높아지는 성질을 함께 보여주고 있어요.

명시적 기준값이 다른 다이오드의 일반형 제목은 **“다이오드 옆 숫자와 측정값은 왜 다른가요?”**, 첫 문장은 **“수업에서는 다이오드 양끝의 전압을 일정한 값으로 놓고 살펴보기도 해요.”**로 대체한다. 회로가 ON/OFF 중인지 확정되지 않으면 이 설명을 생성하지 않는다.

### H05. 다이오드 — 순방향인데 왜 문제가 생겼나요?

> 다이오드는 한쪽 방향으로 전류를 잘 흐르게 하지만, 흐르는 양까지 스스로 제한하지는 못해요. 전류가 너무 많이 흐르면 내부에서 열이 많이 나고 손상될 수 있어요.
>
> 지금은 다이오드가 감당하기 어려울 만큼 많은 전류가 흐르고 있어요.

`forwardCurrent`의 본문이다. `power`만 원인이면 아래 본문을 사용해 전류 한계까지 넘었다고 단정하지 않는다.

> 다이오드도 전류가 흐르면 전기 에너지의 일부가 열로 바뀌어요. 순방향으로 연결했더라도 짧은 시간에 열이 너무 많이 나면 손상될 수 있어요.
>
> 지금은 다이오드 안에서 너무 많은 에너지가 열로 바뀌고 있어요.

두 본문의 파손형은 마지막 문장을 **“지금은 다이오드가 감당하기 어려운 상태여서 손상된 모습으로 보여주고 있어요.”**로 바꾼다. 저항을 넣으면 항상 안전하다거나 저항이 없으면 반드시 파손된다고 말하지 않는다.

### H06. 다이오드 — 전류가 안 흐르는데 왜 위험한가요?

> 다이오드는 반대 방향의 전류를 막아 주지만, 반대 방향의 전압을 얼마든지 견디는 것은 아니에요. 너무 큰 역방향 전압을 걸면 전류를 막는 성질이 무너지고 손상될 수 있어요.
>
> 지금은 전류가 0으로 보이더라도, 다이오드 양끝의 역방향 전압이 너무 크다는 점을 보여주고 있어요.

역방향 전류 0 A가 확인될 때의 제목이다. 전류를 확인할 수 없으면 **“역방향인데 왜 위험한가요?”**로 바꾸고 마지막 문장은 **“지금은 다이오드 양끝에 걸린 역방향 전압이 너무 큰 상태예요.”**로 쓴다. 파손 상태에서는 **“왜 역방향 전압으로 손상됐나요?”**를 제목으로 쓰고 마지막 문장은 **“지금은 너무 큰 역방향 전압을 받아 손상된 모습으로 보여주고 있어요.”**로 바꾼다. 항복 전류·누설 전류·그로 인한 현재 발열을 계산했다는 문구는 금지한다. 화면의 0 A를 실제 항복 이후에도 반드시 0 A라는 뜻으로 일반화하지 않는다.

관련 질문: **실제로도 전류가 안 흐르나요?**

> 실제 다이오드는 역방향 전압이 너무 커지면 반대 방향으로도 전류가 흐를 수 있어요. 이 화면은 그때의 전류까지 나타내지는 않고, 큰 역전압의 위험을 알려주고 있어요.

### H07. 저항·가변저항 — 저항도 손상될 수 있나요?

> 저항은 전류를 줄여 주지만, 그 안에서도 전기 에너지가 열로 바뀌어요. 짧은 시간에 너무 많은 열이 나면 저항도 손상될 수 있어요.
>
> 지금은 저항이 감당하기 어려울 만큼 열이 많이 나는 상태를 보여주고 있어요.

파손형은 마지막 문장을 **“지금은 저항이 감당하기 어려운 상태여서 손상된 모습으로 보여주고 있어요.”**로 바꾼다. 가변저항에도 같은 설명을 사용한다. `저항값을 낮추면 그 저항의 발열이 반드시 증가한다`는 일반화는 하지 않는다. 전체 회로에 따라 전류·전압이 함께 달라진다. `열이 많이 나는 상태`는 소비전력의 의미이며 현재 온도나 누적된 열의 측정이라는 뜻이 아니다.

## 6. 배치·조작·접근성

### 2D와 3D

- 설명의 대상은 부품 ID로 고정한다. 2D는 기존 SVG 부품/라벨 위치를, 3D는 기존 화면 투영 라벨 위치를 받는다. 각각의 렌더러가 문구·등장 조건을 다시 판단하지 않는다.
- 3D 물음표는 입체 물체가 아닌 화면상의 버튼이다. 카메라 방향에 따라 뒤집히거나 가려지는 별도 3D 기호를 만들지 않는다. 파손 뒤에는 남아 있는 바닥 부품 위치에 붙인다.
- 팝업이 열려 있으면 같은 부품을 가볍게 강조하되 선택·탐침·카메라 상태는 바꾸지 않는다. 물음표 클릭은 부품 선택, 값 편집, 탐침 배치, 카메라 드래그로 전파하지 않는다.
- 부품 이름·값·탐침·위험 표식·공통 도구와 충돌하면 기존 라벨 배치의 후보 위치를 활용한다. 44px 누를 영역까지 충돌 검사에 포함한다. 자리 확보가 안 되면 해당 부품의 화면상 물음표는 숨기고 선택 부품의 기존 상세 영역에 같은 설명 버튼을 제공한다. 새로운 자동 줌이나 회로 이동을 만들지 않는다.
- 선택 부품의 상세 영역에 제공하는 버튼은 잠긴 값 편집 `fieldset` 바깥에 둔다. 선택이 잠금을 해제하거나 손상 효과를 재시작하지 않는다.
- 화면 밖 대상의 팝업은 남겨 두지 않는다. 2D 이동·줌, 3D 카메라 이동 시작, 화면 크기 변화, 2D/3D 전환 시 닫는다. 닫기와 설명 선택 때문에 회로를 다시 해석하지 않는다.

### 팝업과 작은 화면

- 기존 `FloatingPanel`의 위치 보정·포털·닫기·키보드 처리를 재사용한다. 폭은 기본 300px, 최대 뷰포트 폭 − 16px다. 새 팝업 위치 계산기를 만들지 않는다.
- 부품 설명의 첫 화면은 제목·본문·닫기와 필요한 관련 질문만 둔다. 내용을 펼치기 위해 긴 수식 설명을 기본으로 스크롤하게 하지 않는다. 좁거나 낮은 화면에서만 기존 패널의 높이 제한과 내부 스크롤을 허용한다.
- 모바일에서도 탭으로 같은 본문을 연다. 설명 때문에 별도 전체 화면·하단 시트를 만들지 않는다. 초기화 버튼, 측정 바, 3D 카메라 도구, 측정표와의 겹침을 확인한다.
- 물음표를 여는 순간 기존 진단/설명 팝업과 상호 배타적으로 닫는다. 기록표·측정 도구 선택은 유지한다. 관련 질문을 바꿀 때 초점은 새 질문 제목으로 옮기고, 명시적으로 닫으면 열었던 버튼으로 돌아간다.

### 접근성

- 용어는 툴팁이지만 클릭해서 읽는 UI이므로 HTML 버튼과 **비모달 dialog**를 사용한다. 긴 설명을 `title` 속성이나 hover 전용 `role=tooltip`에만 넣지 않는다.
- 버튼 이름은 `V₁: 전지 전압 설명`, `D₁: 역전압 설명`처럼 실제 화면 이름을 사용한다. 저장 ID를 읽히게 하지 않는다.
- 사용자가 열기 전에는 본문으로 초점을 이동하지 않는다. 과부하·파손 사건의 기존 알림을 재사용하며 물음표가 생긴 사실을 연달아 별도 방송하지 않는다.
- 읽는 동안 자동 조절로 정상→위험이 바뀌면 이전 설명을 닫는다. 여전히 존재하는 트리거로 초점을 복귀시키고, 트리거가 사라졌다면 현재 모드의 기존 도구 영역으로 이동한다. 이미 닫혀 있던 팝업 때문에 초점을 이동하지 않는다.
- 같은 단계라도 전류 방향·선택된 모델·설명 대상이 바뀌어 현재 주제/변형이 더는 성립하지 않으면 닫는다. 단순한 값 갱신으로 같은 일반 설명이 여전히 유효한 경우에는 읽기를 방해하지 않는다.
- 동작 줄이기 설정에서도 동일 설명을 제공한다. 열림 수명은 `breaking`→`broken` 사건을 따르고 효과의 500ms를 복제하지 않는다.

## 7. 엣지케이스와 금지할 추론

| 사례 | 처리·설명 |
|---|---|
| D₁만 과부하이고 V₁은 정상, V₁ 단자전압은 낮음 | D₁의 원인 설명과 V₁의 H01 제공. V₁이 파손됐다고 말하지 않음 |

| 다이오드 역전압 초과, 전류 0 A | H06. 가짜 누설·항복 전류나 발열을 설명하지 않음 |

| 정상인데 부품 계산, 과부하 없이 `≈` 존재 | 선택 부품의 H01/H02/H04 중 조건에 맞는 설명만. ≈ 자체를 이유로 물음표나 위험 경고를 만들지 않음 |

| 계산값의 차이가 화면 반올림으로 같아 보임 | 물리적 판정은 바꾸지 않음. H01은 “설정 전압과 측정값은 왜 달라질 수 있나요?”라는 일반 질문으로 전환해 보이지 않는 차이를 단정하지 않음. 비교는 숫자와 단위만 같은 표시 정책으로 정규화하고 ≈ 자체는 제외 |

| 3D의 한 절점 높이가 설정 전압보다 낮음 | 절대 전위/높이를 전지의 단자전압으로 오인하지 않음. 두 단자의 전압차를 근거로 함 |
| 독립된 회로가 같은 화면에 있음 | 다른 연결 성분까지 위험 설명을 자동 전파하지 않음. 앱의 기존 세션 전체 잠금/측정 중단 범위는 변경하지 않음 |
| 여러 부품, 같은 부품의 전류·전력 동시 초과 | 기존 대표 순서와 한 부품 한 물음표 유지. 같은 발열 설명을 중복하지 않음. 확인된 추가 원인은 관련 질문으로 연결 |
| 과부하로 자동 조절 정지·지연 입력 도착 | 기존 명령 잠금 유지. 팝업 열림·닫힘은 입력 적용이나 자동 조절 재개를 요청하지 않음 |
| 파손 직후 전원의 직전 단자전압을 설명하려는 경우 | 현재값처럼 보여주지 않음. 파손 부품의 확인된 물리적 원인만 제공하며 직전값 스냅샷 UI는 추가하지 않음 |
| 숫자 숨김·활동 권한·측정 제한 | 설명을 열어 숨긴 숫자·정답·금지 측정을 우회하지 않음. 부품의 일반적 원인 설명만 유지 |
| 초기화 후 아무것도 고치지 않고 재분석 | 새 세션에서 같은 설명 재생성. 읽음 표시로 숨기지 않음. 초기화가 자동 수리·조건 개선이라는 안내 금지 |
| 측정표의 이전 회로 보기·출력·저장·재접속 | 현재 설명을 과거 기록으로 전달하지 않음. 출력과 저장에 물음표·열림 상태·문구·읽음 상태를 포함하지 않음 |
| 줌·화면 밖 이동·다중 터치·포인터 취소 | 열려 있던 설명 닫기. 의도하지 않은 부품 선택/탐침 배치/설명 열림을 막고 카메라·회로 위치 보존 |

전류 0, 미정, 수치 근사, 물리적 근사는 서로 다른 상태다. 하나의 `정상/오류` 플래그로 합치지 않는다.

## 8. 최소 모듈 구조

설명은 app의 작은 기능 폴더로 모은다. 계산 모듈·부품 기호·효과 SVG·도움말 문구를 서로 섞지 않는다. 새 패키지, 플러그인 레지스트리, 범용 규칙 엔진, 설명용 상태 머신은 만들지 않는다.

```text
src/app/operating-help/
  index.ts             공개 함수·컴포넌트·필요 타입만 재노출
  topics.ts            설명 ID, 제목·본문·원인별 변형·관련 질문
  resolve.ts           기존 분석 근거 → 설명 후보·우선순위 (순수 함수)
  layout.ts            44px 터치 영역과 라벨·도구 충돌 배치 (순수 함수)
  OperatingHelp.tsx    공통 ? 버튼·본문, FloatingPanel 재사용
  operating-help.css   ?와 본문 표현만
```

위 경로로 구현했다. 폴더 내부에서는 구현 파일을 직접 참조하고 외부에서는 `index`만 사용한다. 내부에서 자기 `index`를 역참조하여 순환 의존을 만들지 않는다.

### 입력·출력의 경계

`resolve.ts`는 `CircuitDocument`, 공개 컴파일 정보, 선택된 `SimulationResult`, 세션의 현재 단계/확정 assessment, 기존 선택·측정 대상을 읽는다. 회로를 다시 풀지 않고 필요한 경우 기존 `queryVoltage`·`queryCurrent` 공개 질의를 사용한다. 값의 방향은 `rational.direction`을 사용하며 이미 있는 `OperatingCause`의 값·원인·경계를 다시 계산하지 않는다. 전원 가지전류의 기존 +→− 규약을 공급 방향으로 정규화하는 처리는 한곳에 둔다.

출력은 다음의 작은 뷰 모델을 사용한다.

```ts
interface OperatingHelpItem {
  key: string;             // 대상 + 단계 + 질문 변형. 부품 이름·좌표와 무관
  componentId: string;
  label: string;           // 회로에 보이는 이름
  questions: HelpQuestion[]; // 기본 질문 + 관련 질문 최대 두 개
  automatic: boolean;     // 선택/직접 측정 또는 원인과 연결된 부품
}
```

`HelpQuestion`은 닫힌 주제 집합과 파손·일반형·0 A 여부만 담는다. 값이 없는 경우를 0으로 채우거나 의미 없는 `unknown` 문구를 기본값으로 쓰지 않는다. 알려지지 않은 새 원인은 기존 한 줄 진단을 유지하고 검증된 상세 문구가 등록되기 전까지 상세 설명을 생략한다.

### 렌더러와 열림 상태

```text
문서 + 확정된 분석 결과/원인
             ↓
      resolveOperatingHelp       문구 ID·대상 선택
             ↓
  공통 OperatingHelp UI ← topics 문구
             ↑
  2D 부품 라벨 위치 / 3D 부품 투영 위치
```

- app가 설명 후보와 현재 열림 키를 소유한다. 2D·3D는 앵커 위치와 열기 이벤트만 연결한다. `potential-3d`가 app의 문구 모듈을 import하지 않는다.
- 3D는 기존 라벨 투영 경로를 재사용해 부품 앵커를 app에 전달한다. 필요한 앵커 콜백/오버레이 슬롯만 공개 props로 추가한다. 일반적인 UI 배치 엔진을 추가하지 않는다. 2D도 동일 공통 HTML 버튼을 화면 좌표에 배치하므로 별도 SVG용 도움말 본문을 만들지 않는다.
- 앵커는 기존 화면 투영·뷰 변환을 사용하고 설명 때문에 별도 `requestAnimationFrame` 반복문을 추가하지 않는다. 과부하 판정이나 설명 선택 함수에 화면 좌표를 전달하지 않는다.
- `FloatingPanel`에 선택적 controlled open을 추가해 상호 배타 열림과 카메라 이동 시작 시 닫기를 연결했다. 기존 비제어 호출은 유지한다. 포털·위치 계산·Escape·초점 복귀를 복제하지 않는다.
- 기존 `operatingReason`은 짧은 경고를 계속 담당한다. `topics.ts`는 학생용 확장 설명만 담당한다. 두 곳이 같은 `OperatingQuantity`를 받아야 하며 한국어 문구를 파싱해 원인을 판정하지 않는다.
- `ComponentOperatingMark`, `operatingMarkSvg`, 파열 CSS와 독립이다. 화려한 효과를 수정해도 주제·문구·등장 조건을 수정할 필요가 없다. 설명 표시 지연은 세션 단계만 읽으며 연출 시간 상수를 새로 두지 않는다.
- `CircuitDocument`·측정 기록 스키마·부품 프로필에는 설명 ID·열림·읽음 상태를 추가하지 않는다. 회로 v6·측정 기록 v5 유지. 별도 저장소·분석 이벤트 수집도 추가하지 않는다.

## 10. 근거와 구현 순서

### 문구의 물리적 근거

- 전원 단자전압과 공급 전류의 관계는 `V = E − Ir`이며, 입력 기전력과 단자에서 잰 전압을 구별한다. 내부저항을 단순화한 설명의 근거는 [OpenStax, Electromotive Force](https://openstax.org/books/university-physics-volume-2/pages/10-1-electromotive-force)다. 앱의 부호·특성 계약은 [다이오드 DC 모델 §6](../physics/diode-dc-model.md#6-유한한-부품-특성-모델)을 따른다.
- 저항의 소비전력과 열로 전환되는 에너지는 [OpenStax, Electrical Energy and Power](https://openstax.org/books/university-physics-volume-2/pages/9-5-electrical-energy-and-power)의 설명을 참고했다. 이 일반 원리와 앱에서 온도·열 축적을 계산하는 일은 구별한다.
- 실제 다이오드의 순방향 전압은 전류·조건에 따라 달라지고, 역방향 허용 조건도 별도로 주어진다. [Vishay 1N4148 데이터시트](https://www.vishay.com/docs/81857/1n4148.pdf)는 이 구별을 확인하는 자료다. 해당 부품의 실제 정격·곡선을 앱의 교육용 프로필 수치로 옮기지 않는다. 앱의 고정 프로필과 항복 미계산 범위는 [작동 경계](../physics/circuit-operating-boundaries.md)를 따른다.

본문은 위 원리를 학생에게 맞게 새로 작성했으며 외부 교재의 문장을 복사하지 않는다. UI·우선순위·노출 개수는 사용자 승인에 따른 이 프로젝트의 제품 결정이다.

### 구현 순서

1. 이 문서의 문구·등장 범위를 사용자와 확정하고 요구사항 및 ADR-026에 선택형 설명의 계약을 반영한다. 기존 한 줄 경고 규칙의 적용 범위도 명확히 한다.
2. 순수 설명 선택 함수와 문구 카탈로그를 만들고 OH-01~07을 확인한다.
3. 기존 `FloatingPanel`과 2D/3D 라벨 경로에 연결한다. 설명 대상과 앵커는 부품으로 한정한다.
4. 세션/측정 회귀와 OH-08~16, 데스크톱·390px 화면에서의 문구 길이·겹침·초점을 확인한다. 실제 보조기술·교실 검수는 별도 실적으로 기록한다.

새 계산 모델, 열/시간 시뮬레이션, 파손 후 재해석, 효과 고도화, 전체 도움말 개편, 기록별 설명 재생, 범용 튜토리얼 시스템은 이번 구현 범위에 포함하지 않는다.
