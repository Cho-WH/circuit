### 남은 검증과 후순위

실제 iOS Safari·Android Chrome·태블릿에서 손가락 감각, OS 키보드·텍스트 선택·스크롤·브라우저 문맥 메뉴와 포인터 캡처 순서는 아직 검증하지 않았다. 자동 이벤트 검사는 좌표 변환·캡처를 모킹하며 실제 휴대전화 동작을 대체하지 않는다. 따라서 **최소 터치 경로의 코드 개선은 반영했지만 실기기까지 포함한 최소 지원 완료 판정은 보류**한다. 아래 계획 이력의 사용성 과제도 실제 학생에게 아직 수행시키지 않았다.

## 최초 점검 결론

**터치 지원의 기반은 있지만, 최소한의 조작이 안정적으로 동작한다고 판정하기에는 결함이 남아 있다.** 단자 탭 배선, 선택된 부품의 이동, 2D 화면 이동·핀치, 측정 도구의 단일 포인터 이동은 구현되어 있다. 그러나 새 부품을 도선 위에 탭해 삽입하는 경로가 선택 처리에 가로막히고, 측정 도구와 3D의 다중 터치 처리에는 충돌이 있다.

사용자가 이번에 제시한 **“마우스로 드래그할 수 있는 대상은 터치에서도 길게 눌러 같은 동작을 시작할 수 있어야 한다”**는 기준도 현재 충족하지 않는다. 특히 라이브러리 부품과 아직 선택하지 않은 회로 부품이 해당한다. 기존 UX 문서는 선택 후 탭 배치와 선택 후 드래그를 기본으로 정했으므로, 길게 누르기 부재는 기존 규약 위반과 구별되는 **이번 요청에 따른 보완 사항**이다.

이번 작업은 점검과 보고다. 제품 코드·공개 계약·저장 형식·물리 계산은 변경하지 않았다. 서브 에이전트는 사용하지 않았다.

모바일 UX 권장안은 **탭으로 대상을 고르고, 선택한 대상/손잡이는 바로 끌며, 미선택 대상은 길게 눌러 끌고, 두 손가락은 화면 조작에 사용**하는 방식이다. 드래그 없이도 같은 작업을 끝낼 수 있는 버튼·탭 경로를 함께 둔다. 아래 권장안은 구현 제안이며 현행 규범이나 구현 완료 상태를 뜻하지 않는다.

명확한 빈 공간 배치는 즉시 적용하고 실행 취소를 제공하며, 도선 삽입과 모호한 후보에는 미리보기·확인을 둔다. 축소된 화면에서는 후보를 구별하는 선택 방식을 제공하고, 선택·집기·화면 이동을 시각적으로 구분한다. 화면 키보드와 가로·세로 전환에서도 편집 대상과 확대 배율을 유지하는 것을 권장한다.

## 점검 범위와 판단 기준

- 대상: 라이브러리, 2D 캔버스의 배치·선택·이동·배선·값 편집, 측정 탐침/센서, 출력 캔버스, 3D 카메라와 선택, 관련 CSS와 테스트.
- 방법: 이벤트 전달 순서와 상태 수명 분석, 기존 관련 테스트 실행, 의심 경로의 임시 React/DOM 이벤트 검사.
- 제외: 실제 휴대전화·태블릿 조작, 모바일 브라우저의 네이티브 드래그 지원 여부, 화면 키보드·스크롤·문맥 메뉴의 실기기 검증, 전체 접근성 검사. 이번에는 브라우저 시각 검사를 수행하지 않았다.
- 여기서 **이벤트 재현**은 happy-dom에서 실제 React 핸들러를 실행했다는 뜻이다. 좌표 변환·포인터 캡처·일부 hit test는 모킹했다. 실제 모바일 브라우저에서 재현 완료했다는 뜻은 아니다.

관련 규범은 [EDT-001~005, MEA-001~004, VIS-004, TCH-002, QLT-001](../../requirements/requirements.yaml), [상호작용 규칙](interactions.md), [완료 조건](../implementation/definition-of-done.md), [ADR-001](../../decisions/ADR-001-svg-editor.md), [ADR-002](../../decisions/ADR-002-state-management.md), [ADR-013](../../decisions/ADR-013-wire-editing-ux.md)이다. 측정·전위의 물리 규약과 현재 단계도 함께 확인했다. QLT-001의 전체 기기 검증은 단계 7 범위이며, 이번 점검을 그 단계 완료로 보지 않는다.

우선순위는 이 보고서의 수정 제안이다. **P1**은 우선 해결할 기본 편집 경로, **P2**는 뒤이어 해결할 충돌·조작 누락, **P3**는 최소 지원 이후 개선 후보다.

## 상세 발견 사항

### T01 · P1 · 도선 위 터치 삽입이 선택으로 바뀜 — 이벤트 재현

**조건/절차:** 충분히 긴 도선이 있는 회로에서 라이브러리의 저항을 선택하고, 삽입 가능한 도선 중앙을 탭한다.

**기존 계약 기준 기대:** 마우스와 같이 해당 지점으로 `placeAt`을 호출하고 직렬 삽입한다. 아래 모바일 UX 권장안에서는 구조가 바뀌는 삽입에 후보 확인 단계를 제안하지만, 현재 코드는 삽입 후보 흐름에도 진입하지 못한다.

**현재:** `onPlace` 호출은 0회이고 `onWire`가 호출된다. App에서는 도선만 선택한다. 터치 배치 분기에 도달하기 전에 이벤트 처리가 끝난다.

근거: [CircuitCanvas.tsx](../../src/app/CircuitCanvas.tsx) 163–171, 179–198행. 배치 중에는 `wiring.active`가 false다. 이때 터치 클릭의 단자/도선 처리가 `placement`보다 먼저 실행되며, 도선 분기는 즉시 반환한다. 마우스는 211–215행의 `pointerdown` 배치 경로를 사용한다. [App.tsx](../../src/app/App.tsx) 178–181행의 `onWire`는 만들기 모드에서 선택만 변경한다.

임시 비교 검사에서 **같은 `(500, 400)` 도선 지점에 마우스는 `onPlace('resistor', …, {wireId:'W', segment:0})`를 1회 호출하고 터치는 `onWire`만 1회 호출**했다. 터치 클릭 대상 복원은 `elementFromPoint`를 해당 도선으로 모킹했다.

**수정 방향:** 활성 도구의 작업을 먼저 판정하고, 배치 중 탭을 단자/도선 선택으로 보내지 않는다. 아래 권장안을 채택하면 도선 탭은 삽입 후보·기호·양쪽 배선의 미리보기로 연결하고, 후보 확인 후 기존 삽입 명령을 실행한다. 모호한 후보는 먼저 사용자가 구별해 고르게 한다.

**수용 기준:** 같은 위치에 마우스/터치로 놓은 결과 문서가 같아야 한다. 삽입 시 양쪽 배선과 1회 undo/redo를 검증하고, 전압계·공간 부족·교차 근처 거절 동작은 유지한다. 관련: EDT-001, ADR-013.

### T02 · P1 · 길게 눌러 끌기 진입이 없음 — 구현 누락 및 이벤트 재현

**라이브러리:** [App.tsx](../../src/app/App.tsx) 240행은 HTML `draggable`/`onDragStart`/`onDragEnd`와 클릭 배치를 제공한다. 길게 누르기 시간·움직임 판정, 터치 포인터 추적, 캔버스로 넘기는 드래그 세션이 없다. 네이티브 HTML 드래그가 특정 기기에서 작동하는지는 이번 점검에서 확인하지 않았으며, 모든 모바일 환경에서 작동한다고 가정할 수 없다.

**캔버스:** [CircuitCanvas.tsx](../../src/app/CircuitCanvas.tsx) 167–170행은 이미 선택된 몸체인지로 화면 이동 여부를 결정한다. [useTouchNavigation.ts](../../src/app/useTouchNavigation.ts) 13–44행에는 누른 시간에 따라 모드를 바꾸는 로직이 없다. 임시 검사에서 **미선택 부품을 900ms 누른 뒤 움직여도 부품 이동은 0회이고 viewBox만 바뀌었다.**

선택된 부품, 출력 라벨·화살표, 측정 손잡이는 이미 포인터 드래그를 받으므로 누르고 기다린 뒤 끌 수도 있다. 이 동작들까지 모두 미지원으로 분류해서는 안 된다.

**수정 방향:** 라이브러리와 미선택 몸체에 길게 누르기 진입을 추가한다. 대기 중 움직이면 스크롤/화면 이동으로 넘기고, 성립하면 시각적 피드백과 배치/이동 미리보기를 제공한다. 두 번째 손가락·취소·모드 변경으로 폐기한다. 기존 탭 배치·선택 후 드래그는 유지한다. 대기 시간과 허용 이동량은 아직 결정하지 않은 구현/사용성 조정값이다.

**수용 기준:** 라이브러리 → 빈 공간/도선, 미선택 몸체 → 새 위치를 길게 눌러 끌 수 있어야 한다. 취소는 문서와 기록을 바꾸지 않고, 놓기는 정확히 1회 반영하며 후속 클릭이 배선·재배치를 일으키지 않아야 한다. 기존 UX/ADR-013의 미선택 몸체 이동 규칙에 예외가 생기므로 구현 시 관련 문서와 테스트를 함께 갱신한다. 관련: EDT-001/005, 이번 사용자 요청.

### T03 · P2 · 측정 도구가 두 번째 손가락과 충돌 — 이벤트 재현

두 경로를 확인했다.

1. **손잡이 → 같은 손잡이에 두 번째 터치:** [MeasurementLayer.tsx](../../src/app/measurement-tools/MeasurementLayer.tsx) 37행은 기존 `drag` 소유 포인터 검사 없이 새 세션을 넣는다. 첫 손가락의 이동 중 두 번째 손가락으로 다시 눌러 이동·해제하면 두 번째 포인터의 측정 위치가 반영된다.
2. **손잡이 → 배경에 두 번째 터치:** [CircuitCanvas.tsx](../../src/app/CircuitCanvas.tsx) 166행은 손잡이를 공통 터치 탐색기에서 제외한다. 따라서 배경의 두 번째 손가락이 탐색기에는 첫 손가락으로 등록된다. 화면을 이동하는 동안 손잡이 드래그가 살아 있고, 첫 손가락을 놓으면 측정 위치가 반영된다. 임시 검사에서도 viewBox 변경과 `onPlace` 호출이 같은 제스처에서 발생했다.

첫 번째는 측정 세션 소유권 덮어쓰기, 두 번째는 화면 탐색과 도구 이동의 동시 진행이다. 회로 구조를 변경하는 결함은 아니지만, 사용자가 의도하지 않은 측정 대상과 읽기를 만들 수 있다.

**수정 방향:** 측정 손잡이를 포함한 활성 터치를 공통으로 추적하고, 두 번째 터치부터 도구 이동을 취소할지 다른 터치를 무시할지 일관된 정책을 둔다. 탐색으로 전환한다면 모든 손가락을 뗄 때까지 측정 반영과 후속 클릭을 막는다.

**수용 기준:** 탐침/센서 이동 중 손잡이 또는 배경에 두 번째 손가락을 대도 측정 위치가 우연히 바뀌지 않는다. 취소 후 첫 정상 탭은 바로 동작해야 한다. 통합 캔버스에서 검사한다. 관련: MEA-001~004, EDT-005의 제스처 분리 원칙.

### T04 · P2 · 3D 핀치/회전과 선택 판정이 분리됨 — 핸들러 재현

**조건/절차:** 한 손가락을 대고, 다른 손가락을 회로 대상 위에 댄다. 첫 손가락으로 이동한 뒤 두 번째 손가락을 처음 댄 위치에서 뗀다.

**현재:** [potential-3d/index.tsx](../../src/potential-3d/index.tsx) 233–247행의 `start`는 좌표 한 쌍이다. 두 번째 `pointerdown`이 첫 시작점을 덮어쓰고, `pointerup`은 마지막 시작 좌표와의 거리만 비교한다. 포인터 ID·활성 포인터 수·이동 이력·취소 상태를 확인하지 않는다. 따라서 핀치 중이었어도 놓은 지점에 hit가 있으면 `onSelect`가 호출된다.

임시 검사에서는 ray hit를 `R1`으로 고정했을 때 다음 각각에서 선택 1회를 확인했다.

- 두 번째 손가락을 시작 위치에서 해제.
- 한 손가락을 멀리 움직인 뒤 원위치로 돌아와 해제.
- `pointercancel` 뒤 늦은 `pointerup` 전달. 이는 취소 경계의 방어 로직 검사이며 실제 브라우저의 정상 이벤트 순서라고 주장하지 않는다.

OrbitControls 자체의 터치 기능 부재는 아니다. 설치된 Three.js 소스의 기본값은 한 손가락 회전·두 손가락 확대/이동이며, 앱의 별도 선택 판정이 그 제스처 상태를 공유하지 않는다. 테스트에서는 OrbitControls/WebGL을 모킹했으므로 실제 카메라 이동과의 통합은 실기기에서 추가 확인해야 한다.

**수정 방향:** 단일 포인터 탭 후보를 유지하다가 이동 임계값 초과·다중 터치·취소 시 폐기한다. 시작 위치로 돌아와도 탭 후보를 되살리지 않는다.

**수용 기준:** 회전·핀치·취소 직후 선택 콜백은 0회이고, 다음 정상 단일 탭은 1회다. 관련: VIS-004, ADR-006.

### T05 · P2 · 출력 캔버스에 핀치 확대가 없음 — 이벤트 재현

[OutputCanvas.tsx](../../src/app/OutputCanvas.tsx) 130–144행은 다른 포인터가 들어오면 현재 제스처를 취소하고 반환한다. 두 포인터 사이 거리·중심을 계산하는 경로가 없다. [ux.css](../../src/app/ux.css) 114행은 출력 캔버스에 `touch-action:none`을 지정한다.

임시 검사에서 두 손가락을 대고 간격을 벌려도 viewBox는 같았고 문서 명령은 실행되지 않았다. **안전하게 편집을 취소하지만 확대 동작은 수행하지 않는 상태**다. 확대/축소/전체 맞춤 버튼은 168행에 있어 확대 자체가 불가능한 것은 아니다.

**수정 방향:** 출력에서도 두 손가락 화면 이동·확대를 제공하고 라벨/화살표 드래그와 배타적으로 동작하게 한다.

**수용 기준:** 핀치 중심을 기준으로 확대하고, 진행 중 표기 드래그를 취소하며, 손가락을 모두 뗀 후에도 표기 위치·주석·문서 기록은 유지한다. 관련: TCH-002, EDT-005와 모드 간 조작 일관성.

### T06 · P2 · 터치 배치 중 미리보기를 원하는 지점으로 옮길 수 없음 — 이벤트 재현

[CircuitCanvas.tsx](../../src/app/CircuitCanvas.tsx) 80행에서 배치 미리보기의 초기 좌표는 화면 중심으로 정해진다. 터치 배치 모드에서는 170행의 탐색기가 동작을 가져가고, 174행에서 이동 이벤트 전파를 중단하므로 221행의 `setPointer`까지 도달하지 않는다. 이 상태에서 드래그하면 화면이 이동한다.

임시 검사에서 터치 드래그 뒤 viewBox는 변했지만 **미리보기의 문서 좌표/기호 마크업은 그대로**였다. 단순 빈 공간 탭은 197행에서 직접 배치하므로, 탭하기 전에 그 지점의 기호·단자·삽입 경로를 확인하는 단계가 없다. `여기에 배치` 버튼은 290행에서 기존 `pointer` 좌표를 사용한다. 미리보기는 표시되지만 손가락으로 목표 지점을 조절하는 경로가 불완전하다.

**수정 방향:** T02의 길게 눌러 끌기에 위치 미리보기를 연결한다. 명확한 빈 공간의 탭 배치는 해제 시 즉시 적용하고 실행 취소를 제공한다. 도선 삽입은 후보와 최종 연결 경로를 먼저 보여 준 뒤 확인한다. 겹친 후보는 임의로 고르지 않는다. 눌림·미리보기·확정 단계를 구분하여 빈 공간에도 일괄적인 추가 확인을 요구하지 않는다.

**수용 기준:** 터치로 조절한 마지막 미리보기와 놓은 결과가 일치하고, 화면 이동이 미리보기 이동으로 오인되지 않는다. 관련: EDT-001, 상호작용 규칙의 배치 전 미리보기.

### T07 · P3 · 복수 선택의 터치 대안이 없음 — 정적 확인

[CircuitCanvas.tsx](../../src/app/CircuitCanvas.tsx) 255–257행의 추가 선택은 `shiftKey`에 의존한다. 터치 클릭은 196행에서 `onSelect(id)`만 호출한다. [App.tsx](../../src/app/App.tsx) 197–201행도 `additive`가 없으면 기존 선택 집합을 교체한다.

복수 선택이 만들어지면 그룹 이동·정렬을 실행할 수 있지만, 외부 키보드 없이 그 집합을 만드는 UI는 없다. 단일 부품 중심의 최소 지원에서는 후순위로 둘 수 있다. 향후 선택 추가 모드 등 명시적인 터치 대안이 필요하다. 관련: EDT-005.

## 유지할 구현과 실기기 확인 항목

다음 구조는 이미 있으므로 수정 과정에서 보존한다.

- 배선은 확대율에 맞춘 단자 44px·도선 32px 판정과 겹친 후보 선택을 제공한다. [wiring/model.ts](../../src/app/wiring/model.ts) 24–52행, [WiringOverlay.tsx](../../src/app/wiring/WiringOverlay.tsx).
- 2D 선택 부품 드래그는 포인터 ID로 소유권을 확인하고, 문서·도구·권한 변경과 취소·캡처 손실·초점 이탈에 미리보기를 폐기한다. 두 번째 터치의 핀치 진입도 드래그를 취소한다.
- 출력의 단일 포인터 드래그는 미리보기 후 한 번의 명령으로 반영된다. 취소는 원본을 보존한다.
- 측정 도구의 기본 탭 배치·단일 손가락 이동은 구현되어 있다. 측정 대상은 문서 밖의 일시 상태다.
- 회전·복사·삭제와 값 적용/취소에 화면 버튼이 있어 키보드만 요구하지 않는다.

다음은 코드만으로 확정하지 않은 실기기 확인 항목이다.

| 확인 항목 | 코드상 단서 | 확인할 내용 |
|---|---|---|
| 모바일 라이브러리 스크롤과 길게 누르기 | 가로 스크롤 패널, HTML draggable | 스크롤·드래그·문맥 메뉴의 충돌, 캔버스 밖에서 시작한 포인터 인계 |
| 작은 부품 선택 도구·3D 표지 | 선택 도구 최소 높이 34px, 3D 표지는 글자/패딩 중심 크기 | 손가락으로 목표 선택이 가능한지, 인접 버튼 오작동 여부 |
| 축소된 단자·출력 라벨·기호 | 확대율에 맞춘 단자 판정, 화살표 손잡이는 `22 / screenScale`, 부품 몸체는 문서 좌표 48×48 | 목표 크기뿐 아니라 후보 간 간격·겹침·식별 가능성을 함께 확인. 전체 최소 44px 지원으로 보지 않음 |
| 3D 글자 표지 위에서 시작한 드래그 | DOM 표지 `pointer-events:auto`, OrbitControls는 WebGL canvas에 연결 | 표지를 만졌을 때 카메라 드래그 시작이 막히는지 |
| 인라인 편집·키보드·화면 회전 | 입력 자동 focus, 캔버스 높이에 맞춘 편집창 위치 | 대상과 적용/취소의 동시 가시성, 확대 배율·입력 초안·선택 유지, 안전 영역과 시야 복귀 |
| 운영체제 취소·캡처 손실 | 모듈마다 별도 세션과 취소 로직 | 앱 전환·알림·화면 가장자리 제스처·다시 진입 후 첫 조작 |

## 최초 점검의 검증 결과와 테스트 공백

기존 관련 테스트를 다음 명령으로 실행했다.

```text
node node_modules/vitest/vitest.mjs run tests/canvas-drag.test.ts tests/context-wiring.test.ts tests/measurement-workspace.test.ts tests/output-canvas.test.ts tests/potential-3d-lifecycle.test.ts
```

**결과: 5개 파일, 57개 테스트 통과.** 기본 샌드박스에서는 esbuild의 상위 디렉터리 접근 제한으로 시작하지 못했다. 같은 로컬 명령을 허용된 권한 확장으로 실행해 결과를 얻었다. 전체 테스트·타입 검사·빌드는 실행하지 않았다.

추가로 제품 코드 변경 없이 임시 관찰 테스트를 만들고 실행했다.

| 임시 검사 | 결과 |
|---|---|
| 도선 위 터치 삽입 / 같은 지점의 마우스 배치 비교 | 터치 선택 1회·배치 0회 / 마우스 배치 1회 |

| 미선택 몸체 900ms 유지 후 이동 | 화면 이동, 부품 이동 0회 |
| 센서 이동 중 두 번째 손잡이 터치 | 두 번째 포인터 위치 반영 |
| 센서 이동 중 배경 두 번째 터치 | 화면 이동과 센서 위치 반영 동시 발생 |
| 출력 두 손가락 간격 확대 | viewBox 불변, 편집 명령 0회 |
| 3D 두 번째 손가락 해제 / 왕복 드래그 / 취소 후 늦은 해제 | 모킹된 hit 대상 선택 각각 1회 |

**임시 2D/측정/출력 관찰 7개와 3D 핸들러 관찰 3개가 예상한 현재 동작을 확인했다.** 잘못된 동작 자체를 관찰값으로 단언한 검사이므로, 통과를 기능 정상 판정으로 해석하지 않는다. 임시 테스트 파일은 점검 후 제거했으며 정식 회귀 테스트는 수정 시 기대 동작을 기준으로 추가해야 한다.

기존 테스트가 문제를 놓치는 이유도 확인했다.

- `canvas-drag.test.ts`의 터치 부품 이동은 이미 선택된 부품에서 시작한다. 라이브러리에서의 길게 누르기와 도선 위 터치 배치를 검사하지 않는다.
- `measurement-workspace.test.ts`는 캔버스 탭/화면 이동과 단독 `MeasurementLayer`의 손잡이 이동을 나누어 검사한다. 부모 캔버스와 손잡이가 함께 있는 다중 터치 경로가 빠져 있다.
- `output-canvas.test.ts`의 헬퍼는 포인터 ID 1을 사용한다. 마우스/터치 문자열을 바꾸지만 두 손가락 시퀀스는 다루지 않는다.
- `potential-3d-lifecycle.test.ts`는 렌더러와 OrbitControls를 모킹해 준비·수명·전환을 검사한다. 실제 카메라 제스처와 선택의 경합을 보장하지 않는다.

## 모바일 UX 디자이너 관점의 권장안

### 보이는 탭 경로와 길게 눌러 끌기를 함께 제공

**길게 누르기는 집어 옮기는 보조 경로로 제공하고, 조작을 알아내기 위한 필수 조건으로 만들지 않는 것을 권장한다.** 처음 사용하는 학생은 보이는 부품과 버튼을 탭해 회로를 만들 수 있어야 한다. Apple은 익숙한 제스처 의미, 즉각적인 피드백, 제스처 외 대체 입력을 권장한다. Android도 모든 행동을 제스처에만 의존하지 않도록 안내한다. [Apple Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures/), [Android Accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility).

드래그 대안은 키보드 단축키만으로 충분하지 않다. 회로 부품은 `이동` → 목적지 탭 → `놓기`, 측정 도구는 도구 선택 → 접점 탭, 출력 위치는 이동 버튼이나 작은 방향 버튼으로도 조절할 수 있게 한다. 이는 이 앱에 대한 설계 제안이며, 드래그 없이 단일 포인터로 같은 기능을 수행하도록 하는 지침에 근거한다. [W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements), [W3C G219](https://www.w3.org/WAI/WCAG22/Techniques/general/G219).

### 권장 터치 조작표

아래는 **향후 권장 동작**이다. 앞의 현재 지원 표와 구분한다. 만들기·측정·출력 사이에서 선택/이동/핀치의 의미를 최대한 통일하되, 3D 한 손가락은 카메라 회전이라는 별도 맥락을 유지한다.

| 대상/상황 | 권장 조작 | 보이는 반응과 결과 |
|---|---|---|
| 라이브러리 부품 → 명확한 빈 공간 | 부품 탭 → 빈 공간 탭 | 해제 시 한 번 배치하고 선택 유지. 추가 확인 없이 실행 취소 가능 |
| 라이브러리 부품 → 도선 삽입 | 부품 탭 → 도선 후보 탭 → `삽입` | 기호·방향·양쪽 연결을 먼저 표시. 다른 후보 탭으로 조정, 취소는 문서 불변 |
| 라이브러리 부품의 빠른 배치 | 길게 눌러 집기 → 끌기 → 놓기 | 빈 공간은 즉시 배치. 도선 위는 후보를 고정하고 연결 미리보기 확인 후 삽입 |
| 라이브러리 가로 탐색 | 누른 직후 가로로 밀기 | 부품을 집지 않고 목록 스크롤. 스크롤 뒤 배치 모드가 켜지지 않음 |
| 미선택 회로 부품/출력 표기 | 탭 | 안정된 선택 윤곽과 이동 가능 표시. 아직 집거나 움직인 상태는 아님 |
| 미선택 회로 부품/출력 표기 | 길게 눌러 끌기 | 선택과 이동 준비를 한 번에 수행. 놓으면 1회 반영 |
| 선택된 대상/명시적 손잡이 | 바로 끌기 | 집힘 표시와 미리보기로 전환. 길게 누르기를 매번 요구하지 않음 |
| 빈 캔버스/미선택 대상에서 짧게 밀기 | 한 손가락 화면 이동 | 대상 집힘 표시는 없음. 선택된 대상 위에서 화면을 옮기려면 두 손가락 사용 |
| 2D/측정/출력 캔버스 | 두 손가락 이동·핀치 | 진행 중 대상 드래그 취소 후 화면 조작. 부품 회전·복사로 해석하지 않음 |
| 단자/분기 배선 | 단자 탭 → 도착 탭, 도선 후보는 확인 | 현행 탭 배선과 모호한 후보 선택 유지. 길게 누르기 강제 없음 |
| 탐침/센서 | 도구 선택 → 접점 탭, 손잡이 직접 끌기 | 활성 도구와 접점 표시. 두 번째 터치가 들어오면 이동 미반영 |
| 회전·복사·삭제 | 선택 도구 버튼 | 일정 각도 회전, 복사 후 새 대상 선택, 삭제 후 실행 취소 가능 |
| 이름·값·스위치 | 값/상태 탭 또는 선택 도구 버튼 | 더블탭을 알아야만 가능한 기능을 만들지 않음 |
| 3D | 한 손가락 회전, 두 손가락 이동·핀치, 정지 단일 탭 선택 | 카메라 조작이 선택으로 끝나지 않음. 시점/초기화 버튼 유지 |

### 배치 확인은 작업 결과에 따라 구분

**명확한 빈 공간에는 빠르게 놓고, 기존 연결 구조가 바뀌거나 대상이 모호할 때 확인한다.** 모든 배치에 `놓기`를 한 번 더 누르게 하면 반복 작업이 느려지므로 일괄 확인은 권장하지 않는다. 이는 이 앱에 대한 UX 제안이며 공식 지침이 정한 특정 탭 횟수는 아니다.

- **빈 공간:** 짧은 탭은 해제 시, 드래그는 놓을 때 한 번 적용한다. 즉시 선택 상태를 유지하고 실행 취소를 제공한다. 눌림 동안의 미리보기는 문서를 변경하지 않는다.
- **도선 삽입:** 탭 또는 드롭으로 후보를 정하고 기호·방향·양쪽 배선의 변경을 표시한 뒤 `삽입`으로 적용한다. 드래그를 끝낸 것과 연결 구조를 확정한 것을 구분한다. 후보 상태에서는 다른 위치로 조정하거나 취소할 수 있다.
- **여러 도선/단자가 겹친 위치:** 대상을 먼저 명시적으로 선택한다. 후보가 하나로 좁혀지기 전에는 삽입·연결하지 않는다. 도선 가까운 위치를 편의상 빈 공간으로 간주해 잘못 배치하지 않는다.
- **드래그 없는 기존 부품 이동:** `이동` → 목적지 탭 → `놓기` 경로를 유지한다. 연결 배선의 변경을 확인하는 대안이며, 새 부품의 단순 빈 공간 배치와 구별한다.

도선 삽입 확인은 현행 터치 즉시 삽입 계약에 대한 변경 제안이다. 기존 마우스 클릭·드롭 동작은 유지하며, 구현 시 상호작용 문서·ADR-013·수용 기준을 함께 정리한다. 입력 방식별 단계 수가 달라도 확정된 문서 결과와 실행 취소 단위는 같아야 한다.

### 길게 누르기와 스크롤의 구분

다음 수치는 **이 앱의 초기 실험값**이며 Apple/Android의 의무 기준이나 확정값이 아니다. 실제 기기에서 손 떨림과 목록 스크롤 성공률을 보고 조정한다.

| 상태 | 제안 규칙 | 피드백/결과 |
|---|---|---|
| 누른 직후 | 즉시 눌림 강조, 약 450ms 집기 대기 | 입력을 받았음을 표시하되 문서는 변경하지 않음 |
| 대기 중 이동 | 시작점에서 약 10 CSS px 벗어나면 집기 후보 해제 | 라이브러리는 스크롤, 캔버스는 화면 이동 |
| 길게 누르기 성립 | 윤곽·작은 상승 표시로 집힘 알림 | 이제 움직이면 대상을 옮긴다는 확신 제공 |
| 성립 후 이동 | 잡은 지점과 대상의 상대 위치 유지 | 대상이 손가락 중심으로 갑자기 튀지 않음 |
| 움직이지 않고 해제 | 기존 대상은 선택, 라이브러리는 탭 배치 경로 | 제자리 복제나 임의 위치 추가 없음 |
| 두 번째 손가락/시스템 취소 | 대기·집기·이동 폐기, 모든 손가락 종료까지 확정 금지 | 원본/기록 유지. 다음 정상 입력부터 새 세션 |

선택된 대상과 눈에 보이는 손잡이는 즉시 끌 수 있게 하고, 같은 손잡이에 길게 누르기 메뉴를 겹쳐 배정하지 않는다. 터치 정책은 화면 너비만이 아니라 실제 입력 종류를 기준으로 적용해 태블릿의 마우스 사용도 유지한다. 스크롤을 살린 상태에서 라이브러리의 길게 누르기를 인식할 수 있는지는 모바일 브라우저에서 반드시 검증한다.

### 손가락에 가리지 않는 미리보기와 정확한 도착점

Apple은 드래그 중 연속 피드백, 반투명 표현과 결과 예측, 드롭 후 선택 유지를 권장한다. 이 앱에서는 아래와 같이 적용한다. [Apple Drag and drop](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop?changes=_3).

- 드래그 대상은 반투명하게, 실제 적용될 격자 위치·양쪽 단자·배선은 정확한 자리에 표시한다. 손가락을 피하려고 실제 도착 좌표를 조용히 바꾸지 않는다.
- 손가락 위쪽의 작은 보조 미리보기/접점 확대는 정밀 조작의 후속 개선으로 고려한다. 제공할 때도 실제 접점 표식을 동시에 남겨 떠 있는 그림과 도착점이 혼동되지 않게 한다.
- 가능 구간은 윤곽과 연결선으로 알린다. 불가능한 위치는 색과 함께 `공간이 부족해요` 같은 짧은 이유를 표시한다. 이동할 때마다 알림창을 띄우지 않는다.
- 후보가 조금 흔들려도 기존 스냅을 유지하는 여유를 두어 미리보기 떨림을 줄인다. 이는 위치 후보 안정화이며 화면 좌표만으로 전기 연결을 추가하는 기능이 아니다.
- 원위치로 돌아오거나 유효하지 않은 영역/캔버스 밖에 놓으면 취소한다. 새 부품은 추가하지 않고 기존 부품·표기는 원위치를 유지한다.
- 빈 공간 드롭 또는 삽입 확인이 끝나면 선택을 유지해 바로 회전·값 수정이 가능하게 하고 실행 취소를 가까운 도구에 둔다. 확인 전 삽입 후보는 완료된 배치와 다르게 표시한다.

### 선택·집기·화면 이동을 눈으로 구별

선택 여부에 따라 같은 한 손가락 움직임이 부품 이동 또는 화면 이동으로 달라지는 규칙은 처음 사용하는 학생에게 어렵다. **선택됨과 집혔음을 서로 다른 상태로 표시**하여 사용자가 다음 동작을 예측하게 한다. 아래는 새로운 제스처를 추가하지 않고 기존 조작을 이해하기 쉽게 하는 제안이다.

| 상태 | 표시와 동작 |
|---|---|
| 선택됨 | 움직이지 않는 윤곽 강조와 이동 가능 표시, 선택 도구를 보여 준다. 선택만으로 대상이 손가락을 따라오지 않는다. |
| 집기 대기 | 눌림 반응을 즉시 보여 주되, 선택 완료/집기 완료와 구별한다. 대기 중 짧게 밀면 화면 이동으로 전환한다. |
| 집힘/이동 중 | 윤곽과 작은 상승·그림자 또는 반투명 표현으로 배경보다 대상을 강조하고 도착 미리보기를 표시한다. 실제 판정 영역은 시각 효과에 따라 흔들리지 않는다. |
| 화면 이동 중 | 회로 전체가 함께 움직이고 개별 대상의 집힘 표시는 제거한다. 선택 자체는 유지할 수 있지만 부품 위치는 바뀌지 않는다. |

길게 누르기가 성립한 시점에 집힘 피드백을 주고, 선택된 대상의 즉시 드래그도 같은 이동 표시를 사용한다. 제스처가 대상 이동으로 정해진 뒤 다른 단자나 배경을 지나갔다고 화면 이동으로 바꾸지 않는다. 두 번째 손가락이나 명시적 취소만 별도 전환 규칙을 따른다. 움직임 감소 설정에서는 상승 애니메이션 대신 윤곽·정적인 손잡이 표시로 상태를 구별한다.

### 화면 조작과 편집은 한 번에 하나만

**두 번째 손가락은 화면 조작 의도로 우선 처리**하는 것이 이 앱의 최소 지원에 적합하다. 부품·탐침·센서·출력 라벨·화살표 이동은 취소한다. 핀치 후 한 손가락만 남았을 때 대상 이동으로 복귀하지 않고, 모든 손가락이 끝날 때까지 편집을 확정하지 않는다.

이미 탭으로 정한 배선 시작점은 화면을 이동해도 유지할 수 있다. 다만 화면 이동/핀치의 해제는 도착 선택이나 연결 완료로 사용하지 않는다. 후보 확인 버튼·텍스트 입력·도구 패널은 캔버스 핀치 영역에서 제외한다.

두 손가락 회전으로 부품을 돌리거나 세 손가락 탭을 실행 취소의 유일한 방법으로 정하는 것은 이번 범위에서 권장하지 않는다. 회전·실행 취소 버튼이면 충분하다. 운영체제와 충돌할 수 있는 화면 가장자리 전용 제스처도 추가하지 않는다.

### 확대율과 밀집도에 맞춘 선택 방식

Android는 시각적 크기와 별도로 최소 48dp 터치 영역을 권장한다. **이 웹앱에서는 독립 버튼 48×48 CSS px를 목표**, 조밀한 캔버스 접점은 기존 44px 판정을 최소 설계 목표로 제안한다. dp와 CSS px를 같은 단위로 간주한 변환이나 WCAG 충족 선언이 아니며, 앱에서 채택할 별도 크기 기준이다. [Android Accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility).

기호의 **보이는 크기, 실제 판정 영역, 이웃 후보와의 간격**을 함께 검토한다. 축소 화면에서 판정 영역만 키우면 서로 다른 단자·몸체·도선이 더 겹칠 수 있다. 목표 크기와 간격을 함께 고려하는 접근은 [W3C 목표 크기 지침](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)을 참고한다. 다음 선택 방식은 이 앱에 대한 설계 제안이다.

| 화면에서의 후보 상태 | 권장 선택 방식 |
|---|---|
| 목표가 충분히 떨어져 있고 후보가 명확함 | 넓은 판정 영역으로 직접 선택. 작은 시각 기호도 쉽게 누를 수 있게 함 |
| 축소·밀집으로 여러 목표가 겹침 | 명확하지 않은 경우 후보를 펼쳐 선택. `R₁ 왼쪽 단자`, `R₂ 위쪽 단자`처럼 대상을 구별하고 원래 위치와 연결 표시 |
| 후보를 펼쳐도 화면 끝에서 겹치거나 잘림 | 캔버스를 강제로 확대/이동하지 않고, 짧은 이름과 위치 관계를 가진 목록으로 제시 |
| 후보 선택 중 확대율이 달라짐 | 후보의 실제 ID를 유지해 다시 배치하거나 후보 UI를 닫고 재선택하게 함. 화면 순서 변화만으로 다른 대상을 선택하지 않음 |

고정된 확대율 숫자만으로 모드를 전환하지 않고 현재 화면에서의 판정 영역 겹침과 후보 구별 가능성을 기준으로 판단한다. 배선 중에는 연결 가능한 접점, 부품 이동 중에는 이미 잡은 몸체처럼 현재 작업에 맞는 대상만 후보로 삼는다. 후보 선택만으로 연결·값·위치를 바꾸지 않으며, 선택 후 확정 단계는 해당 도구의 규칙을 따른다. 선택 후보를 펼치는 기능은 후순위인 접점 확대 미리보기와 별개다.

### 선택 도구와 화면 키보드·회전 시 작업 위치

- 좁은 화면의 선택 도구는 캔버스 아래쪽의 안정된 위치에 둔다. `회전`, `이동`, `삭제` 같은 짧은 이름을 함께 제공하고, 삭제와 놓기/확인은 충분히 구분한다. 단일 삭제마다 확인창을 추가하는 대신 확실한 실행 취소를 제공한다.
- 값 편집은 화면 키보드 위에 적용/취소가 남는 작은 하단 편집 영역을 권장한다. 입력창뿐 아니라 어느 부품을 편집하는지도 함께 볼 수 있게 한다. 키보드·홈 표시 영역·화면 가장자리에 버튼이 가려지지 않도록 실제로 보이는 영역을 기준으로 배치한다.
- 입력 키패드는 `/`, `-`, 소수점과 지원 단위를 입력할 수 있어야 한다. 숫자 키패드 적용 때문에 기존 분수·음전압·단위 입력을 막지 않는다.
- 확대/축소·전체 보기 버튼을 유지한다. 두 손가락을 쓰기 어려운 사용자를 위한 화면 이동 방향 버튼도 보조 도구에서 접근할 수 있게 한다.

안전 영역·키보드를 고려하고 중요한 조작을 닿기 쉬운 곳에 두라는 [Android 레이아웃 지침](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-basics)을 참고해, 이 앱에서는 아래처럼 작업 맥락을 보존할 것을 제안한다.

| 화면 변화 | 보존 및 복귀 규칙 |
|---|---|
| 키보드 열림 | 선택 대상·입력 초안·작업 모드·확대 배율을 유지한다. 대상과 적용/취소를 보이게 하는 데 필요한 만큼만 화면을 이동한다. |
| 키보드 닫힘 | 키보드 때문에 임시로 옮긴 시야만 복구한다. 사용자가 그동안 직접 이동·확대한 경우에는 새 시야를 존중하고 이전 위치로 강제 복귀하지 않는다. |
| 가로·세로 전환 또는 창 크기 변경 | 선택/편집 대상이 새 화면의 유효 영역에 남도록 하고 확대 배율을 가능한 한 유지한다. 임의의 전체 맞춤으로 바꾸지 않는다. 편집 대상이 없으면 보고 있던 회로 지점을 기준으로 유지한다. |
| 드래그 도중 화면 회전 | 진행 중 미리보기만 취소하고 원본·기록·선택을 유지한다. 바뀐 좌표계의 해제 이벤트로 이동을 확정하지 않는다. |

화면이 좁아져 원래 구도를 그대로 유지할 수 없으면 편집 대상의 가시성을 먼저 확보하고 최소한으로 시야를 조정한다. 자동 조정은 회로 부품의 문서 좌표를 변경하지 않는다. 분수·음수 입력 중 화면 회전으로 초안이나 선택 범위가 사라지는지도 실기기에서 확인한다.

### 확인·취소·첫 사용 안내

터치가 닿으면 눌림과 후보를 표시하고, 회로/출력 확정은 손을 놓거나 `놓기`/`확인`을 눌렀을 때 수행한다. 문서 변경 전 취소와 변경 후 실행 취소가 예측 가능해야 한다. 이는 해제 시 활성화와 중단/복구를 설명하는 지침에 근거한 설계다. [W3C Pointer Cancellation](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html).

안내는 첫 사용이나 후보가 모호할 때만 짧게 표시한다. 라이브러리의 `탭해서 놓거나 길게 눌러 끌어오세요`, 배치 모드의 `놓을 곳을 누르세요`, 도선 삽입 후보의 `삽입 · 취소`, 기존 부품의 탭 이동 후보의 `놓기 · 취소`를 구분한다. 빈 공간의 정상 배치에는 별도 확인 UI를 띄우지 않는다. 배선의 상시 설명 버블은 되살리지 않는다. 길게 누르기에는 시각적 피드백을 필수로 하고, 진동은 가능한 환경의 선택적 보조 피드백으로 둔다.

화면 읽기 프로그램에는 아이콘 이름·선택 상태·완료/실패가 전달되어야 한다. 이동 좌표를 매번 읽기보다 집기·놓기·취소 같은 단계 변화를 알린다. 실제 플랫폼 지원과 읽기 순서는 별도 검증한다.

### 구현 범위와 사용성 과제

최소 지원에는 T01 수정, 작업에 따른 배치 확인, 길게 눌러 집기와 탭 대안, 다중 터치 충돌 제거, 선택/집기/화면 이동의 구분, 밀집 후보 선택, 키보드·화면 회전에서의 작업 위치 보존을 우선 포함한다. 목표 크기와 취소·실행 취소도 함께 검증한다. 복수 선택 모드·정밀 접점 확대·가장자리 자동 화면 이동·진동은 첫 구현이 안정된 뒤 검토한다.

코드 검사와 별도로 처음 쓰는 학생에게 다음 과제를 설명 없이 수행하게 하고 **오조작·되돌리기·도움 요청·완료 여부**를 기록한다. 아직 측정하지 않았으며 성공했다고 간주하지 않는다.

| 사용성 과제 | 확인할 기준 |
|---|---|
| 라이브러리를 옆으로 넘긴 뒤 부품 추가 | 스크롤 중 부품이 잡히거나 회로에 생기지 않음 |
| 빈 공간에 부품을 반복 배치하고 직전 배치 취소 | 매번 추가 확인 없이 완료하고 실행 취소로 정확히 한 번 복원함 |
| 선택된 부품 이동과 미선택 부품 위의 화면 이동을 번갈아 수행 | 선택/집힘/화면 이동을 보고 구별하고 의도한 대상만 움직임 |
| 길게 눌러 이동하고, 다시 집어 원위치로 돌아와 취소 | 집힘을 알아차리고 반영/취소를 구분함 |
| 저항을 도선 중앙에 삽입하고 다음 삽입은 취소 | 기호·방향·양쪽 연결을 먼저 이해하고, 확인 전에는 문서가 바뀌지 않음 |
| 회로를 축소한 뒤 가까운 단자와 화면 끝의 후보를 선택 | 후보 이름과 원래 위치로 구별하고 인접 대상을 임의 선택하지 않음 |
| 드래그 중 두 손가락 확대 후 순서를 바꿔 해제 | 부품/측정 대상이 뜻밖에 바뀌지 않고 다음 탭이 동작함 |
| 탭과 버튼만으로 부품 이동·측정·출력 위치 조정 | 키보드나 숨은 제스처 도움 없이 완료함 |
| 확대된 부품에서 분수·음수·단위 입력 후 키보드 닫기 | 대상과 적용/취소가 보이고, 초안·확대 배율·사용자가 정한 시야가 유지됨 |
| 값 편집 및 드래그 중 각각 가로·세로 전환 | 입력 초안과 선택 유지, 드래그는 미반영 취소, 불필요한 전체 맞춤 없음 |

## 최초 구현 순서와 수용 기준 — 계획 이력

1. **기본 편집 경로:** T01의 이벤트 우선순위를 수정하고, T02/T06의 길게 누르기·미리보기 계약을 구현한다. 빈 공간은 즉시 배치와 실행 취소, 도선 삽입은 후보 확인으로 구분한다. 확정된 문서 결과와 기존 마우스 조작을 유지한다.
2. **제스처 충돌과 상태 표시:** 측정 손잡이와 화면 탐색의 포인터 소유권을 정리하고, 3D에서 탭과 화면 조작을 분리한다. 선택/집기/화면 이동의 표시와 취소·다중 터치 이후 잔여 손가락·후속 클릭을 함께 검증한다.
3. **밀집 화면과 작업 맥락:** 출력 핀치와 축소 시 후보 선택을 보완하고, 목표 크기·간격·스크롤·키보드·화면 회전에 따른 시야 보존을 실제 기기에서 확인한다. 복수 선택 UI는 후순위로 관리한다.

수정 후 최소 검증 시나리오는 아래와 같다.

- iOS Safari와 Android Chrome의 실제 터치에서 빈 공간 배치·도선 삽입·기존 부품 이동을 완료하고, 같은 마우스 조작과 결과 문서를 비교한다. 태블릿에서도 대표 흐름을 확인한다.
- 라이브러리 가로 스크롤, 미선택 부품의 짧은 화면 이동, 길게 눌러 부품 이동이 서로 구별되어야 한다.
- 2D·측정·출력에서 두 번째 손가락을 대고 순서를 바꿔 떼어도 편집/측정이 잘못 반영되지 않아야 한다.
- 단자 탭 배선, 도선 후보 확인·취소, 겹친 단자 선택, 스위치와 이름·값 편집을 터치만으로 수행한다.
- 빈 공간 탭 배치는 추가 확인 없이 1회 반영되고, 도선 삽입은 확인 전 문서 불변·확인 후 1회 반영이어야 한다. 축소·밀집·화면 끝에서도 후보의 이름과 위치를 구별할 수 있어야 한다.
- 선택·집기·화면 이동의 표시가 조작 결과와 일치해야 한다. 대상 이동 중 단자/배경 위를 지나도 제스처 의미가 갑자기 바뀌지 않아야 한다.
- 키보드 열기/닫기와 가로·세로 전환에서 편집 대상·입력 초안·선택·확대 배율을 보존한다. 자동 시야 조정은 필요한 최소 범위로 제한하고, 사용자 이동/확대를 되돌리지 않아야 한다.
- 정상 드롭은 한 번의 문서 명령 단위로 기록하고, 취소·핀치·화면 이동은 편집 기록을 만들지 않는다. 문서 변경에는 undo/redo와 관련 fixture 검증을 적용한다.
- 3D 카메라 조작 후 선택이 바뀌지 않고, 정상 단일 탭으로는 선택할 수 있어야 한다.
- 변경된 기대 동작의 자동 회귀 검사와 실기기 결과를 모두 남긴 뒤 최소 터치 지원 완료를 판정한다.

입력 세션·후보·미리보기는 계속 UI 상태에 두고, 회로 편집은 기존 명령 API를 사용하면 된다. 이번 발견 사항 자체는 저장 형식 변경이나 계산 모델 변경을 요구하지 않는다.
