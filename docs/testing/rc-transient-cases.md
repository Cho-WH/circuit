# 선형 RC 계산과 관찰 수용 사례

상태: 2026-10-22 전체 RC 수용 계획. [C0](rc-c0-results.md)·[C1](rc-c1-results.md)·[C2](rc-c2-results.md)·[C3](rc-c3-results.md)·[C4](rc-c4-results.md)의 구현 검증과 [C5](rc-c5-results.md)의 브라우저·키보드·작은 화면·계산 비용을 확인했다. 실제 기기·보조기술·사용자 수용·배포 승인과 자동 검사 결과는 구분한다. 물리 기준은 [RC 규약](../physics/linear-rc-transient.md), UX는 [관찰 기획](../ux/rc-transient.md), 구현 순서는 [설계](../architecture/rc-transient.md#구현-순서와-관문)를 따른다.

## 수치 검증 방법

단일 RC 해석식을 기준으로 삼고, 다중 RC는 독립적인 고정밀 계산과 비교한다. 제품 엔진과 같은 코드를 테스트 안에서 복사해 기대값을 만들지 않는다. 전하·에너지 수지는 기준점 변경·부품 순서 변경·축전기 방향 교환에서도 확인한다.

에너지 검사는 공급원의 일, 저항 소모, 축전기 에너지 변화의 일치를 비교한다. 재생 애니메이션 시간이나 임의의 화면 샘플 합을 참값으로 쓰지 않는다. 평형 전환은 생략된 t→∞ tail의 에너지까지 포함해 비교한다.

수치 잔차와 실제 오차의 차이, 특히 조건수가 큰 입력에서 오차 추정이 과소한지 확인한다. 모드 진폭·감쇠율 불확실성을 포함한 B̂가 기준값의 남은 변화보다 작게 나오면 C0 관문을 통과하지 못한다. 이론적 상한과 binary64 추정의 보장 범위를 결과에 기록한다.

## 실행 경계

C0 시제품은 tools/rc-prototype, 테스트는 tests/rc-prototype.test.ts, 독립 기준값은 tests/fixtures/rc-prototype-reference.json에 둔다. C0는 당시 제품 스키마와 분리한 전용 netlist를 유지한다. C1은 tests/rc-contracts-storage.test.ts의 v7 축전기 문서로 SIM-009·MEA-006·DAT-006의 공개 계약을 검증한다. 기존 FIX JSON은 v7로 옮기되 계산값을 유지했다. C2는 tests/rc-engine.test.ts의 v7 문서와 독립 90자리 기준 자료로 제품 엔진·도선 질의 및 기존 DC 회귀를 검증한다. [C3 결과](rc-c3-results.md)는 RC-12~15·20의 재생·잠금·초기화 및 RC-16의 기록 권한 경계를 검증한다. [C4 결과](rc-c4-results.md)는 RC-12·16~19·21의 공통 관찰·기록·기호·출력을 검증한다. [C5 결과](rc-c5-results.md)의 브라우저·키보드·작은 화면·자동 터치와 실제 기기 수용은 구분한다.

검증은 단계에 직접 관련된 범위부터 실행한다. 전체 테스트를 매 단계 반복하지 않으며 기존 DC·저장·출력에 실제 영향이 생긴 때 해당 회귀 범위를 추가한다. 사용자 동작 확인·자동 검사·공개 배포 확인은 별도로 기록한다.
