# 사용성 검증

## 이번 구현의 검증 범위

자동 검사와 브라우저 조작 확인은 실제 교사·학생의 사용성 연구를 대체하지 않는다. 아래 과제·시간 목표·이해도 질문은 아직 사람 대상으로 검증하지 않았다. 코드 검증은 [검증 범위](mvp-coverage.md), 후속 구현 후보는 [남은 작업](../implementation/follow-up.md)을 따른다.

## 첫 사용자 과제

| 번호 | 과제 | 관찰할 점 |
|---:|---|---|
| 1 | 9 V 전지와 10 Ω 저항 두 개를 직렬로 연결한다. | 부품 찾기, 배치, 단자 인식, 배선 오류 |
| 2 | 두 번째 저항 양단의 전압을 측정한다. | 탐침 방향, 전압계 의미, 부호 해석 |
| 3 | 가장 높은 전위의 지점을 찾고 같은 전위 영역을 표시한다. | 전위와 전위차 구분, 등전위 이해 |
| 4 | 전위 높이 보기로 바꾸고 저항별 전압 강하를 설명한다. | 2D↔3D 대응, 높이 과장 이해 |
| 5 | 저항값 하나를 숨긴 문제지 그림을 복사한다. | 모드 전환, 값 숨기기, 출력 발견성 |

## 관찰 원칙

- 사용자가 막혔을 때 바로 해결 방법을 알려 주지 않는다.
- 먼저 어떤 버튼과 표현을 기대했는지 묻는다.
- 기능 성공 여부와 함께 물리적 오해를 기록한다.
- 도움말을 읽지 않은 상태의 행동을 관찰한다.
- 마우스, 터치, 키보드 환경을 나누어 시험한다.

## 초기 목표

- 첫 부품 배치: 10초 이내
- 직렬 회로 완성: 1분 이내
- 전압 측정: 추가 설명 없이 성공
- 문제지 그림 복사: 2분 이내
- 같은 도선이 같은 전위라는 설명: 시각화 후 구두로 표현 가능

## 이해도 확인 질문

- 왜 이 도선 전체가 같은 색인가?
- 전압계 탐침을 바꾸면 부호가 왜 바뀌는가?
- 병렬 가지가 같은 높이에서 시작하고 끝나는 이유는 무엇인가?
- 열린 스위치에서 전류가 0인데 양단 전위차가 생길 수 있는가?
- 기준점을 바꾸어도 바뀌지 않는 물리량은 무엇인가?

## 후속 UX 평가 과제

교사 5명·학생 5명 내외의 소규모 형성 평가를 제안한다. 모집·실행 결과나 대표 표본이 아니다. 같은 난도·기기로 비교하고 수행 중 설명 요구 대신 종료 후 회고 질문을 한다. 실패는 발견·조작·확인 중 어디에서 생겼는지 기록한다.

| 과제 | 기록할 것 | 목표/판정 |
|---|---|---|
| 처음 들어와 전원 배치 | 시작부터 확정 배치까지 시간, 도움 요청 | 기존 제품 목표 10초 |
| 전원+저항 2개 직렬 완성 | 잘못 연결한 횟수, 취소, 성공 시간 | 기존 제품 목표 1분 |
| R1을 1 kΩ으로 바꾸기 | 입력 위치 탐색, 화면 이동, 결과 확인 | 회로와 입력이 함께 보이는지 |
| R1 전압 측정 후 부호 반전 | 탐침 위치, 부호 설명, 오조작 | 크기 유지·부호 반전 이해 |
| 같은 도선의 전위 설명 | 2D 색·숫자·3D 높이의 대응 설명 | 도선 전압 강하 등 오개념 여부 |
| R1을 ?로 바꾸고 흑백 그림 붙여넣기 | 출력 찾기·미리보기·실제 문서 붙여넣기 시간 | 기존 제품 목표 2분 |
| 기록 후 종료 준비 | 무엇이 저장되는지 답변, CSV 보관 | 회로·기록 보존 범위 구분 |
| 단락 예제 고치기 | 진단 이해, 대상 발견, 수정·되돌리기 | 설명서 없이 원인과 행동 연결 |

데스크톱·태블릿에서는 도선에 저항 삽입 → 병렬 가지 추가 → 교차 연결 → 비연결 복원 → 흑백 출력을 확인한다. 이 결과로 스마트폰의 정밀 편집 지원 수준을 평가한다.

## 실제 터치 사용성 과제

처음 쓰는 학생이 설명 없이 수행하는 동안 오조작·되돌리기·도움 요청·완료 여부를 기록한다.

| 사용성 과제 | 확인할 기준 |
|---|---|
| 라이브러리를 옆으로 넘긴 뒤 부품 추가 | 스크롤 중 부품이 잡히거나 회로에 생기지 않음 |
| 빈 공간에 부품을 반복 배치하고 직전 배치 취소 | 매번 추가 확인 없이 완료하고 실행 취소로 정확히 한 번 복원함 |
| 선택된 부품 이동과 미선택 부품 위의 화면 이동을 번갈아 수행 | 선택/집힘/화면 이동을 보고 구별하고 의도한 대상만 움직임 |
| 길게 눌러 이동하고, 다시 집어 원위치로 돌아와 취소 | 집힘을 알아차리고 반영/취소를 구분함 |
| 저항을 도선 중앙에 삽입하고 다음 삽입은 취소 | 기호·방향·양쪽 연결을 먼저 이해하고, 확인 전에는 문서가 바뀌지 않음 |
| 회로를 축소한 뒤 가까운 단자와 화면 끝의 후보를 선택 | 후보 이름과 원래 위치로 구별하고 인접 대상을 임의 선택하지 않음 |
| 드래그 중 두 손가락 확대 후 순서를 바꿔 해제 | 부품/측정 대상이 뜻밖에 바뀌지 않고 다음 탭이 동작함 |
| 탭과 버튼만으로 부품 이동·측정·출력 위치 조정 | 키보드나 숨은 제스처 도움 없이 완료함 |
| 확대된 부품에서 분수·음수·단위 입력 후 키보드 닫기 | 대상과 적용/취소가 보이고, 초안·확대 배율·사용자가 정한 시야가 유지됨 |
| 값 편집 및 드래그 중 각각 가로·세로 전환 | 입력 초안과 선택 유지, 드래그는 미반영 취소, 불필요한 전체 맞춤 없음 |

## 실기기 수용 검사

- iOS Safari와 Android Chrome의 실제 터치에서 빈 공간 배치·도선 삽입·기존 부품 이동을 완료하고, 같은 마우스 조작과 결과 문서를 비교한다. 태블릿에서도 대표 흐름을 확인한다.
- 라이브러리 가로 스크롤, 미선택 부품의 짧은 화면 이동, 길게 눌러 부품 이동이 서로 구별되어야 한다.
- 2D·측정·출력에서 두 번째 손가락을 대고 순서를 바꿔 떼어도 편집/측정이 잘못 반영되지 않아야 한다.
- 단자 탭 배선, 도선 후보 확인·취소, 겹친 단자 선택, 스위치와 이름·값 편집을 터치만으로 수행한다.
- 빈 공간 탭 배치는 추가 확인 없이 1회 반영되고, 도선 삽입은 확인 전 문서 불변·확인 후 1회 반영이어야 한다. 축소·밀집·화면 끝에서도 후보의 이름과 위치를 구별할 수 있어야 한다.
- 선택·집기·화면 이동의 표시가 조작 결과와 일치해야 한다. 대상 이동 중 단자/배경 위를 지나도 제스처 의미가 갑자기 바뀌지 않아야 한다.
- 키보드 열기/닫기와 가로·세로 전환에서 편집 대상·입력 초안·선택·확대 배율을 보존한다. 자동 시야 조정은 필요한 최소 범위로 제한하고, 사용자 이동/확대를 되돌리지 않아야 한다.
- 정상 드롭은 한 번의 문서 명령 단위로 기록하고, 취소·핀치·화면 이동은 편집 기록을 만들지 않는다. 문서 변경에는 undo/redo와 관련 fixture 검증을 적용한다.
- 3D 카메라 조작 후 선택이 바뀌지 않고, 정상 단일 탭으로는 선택할 수 있어야 한다.
- 변경된 기대 동작의 자동 회귀 검사와 실기기 결과를 모두 남긴 뒤 최소 터치 지원 완료를 판정한다.
