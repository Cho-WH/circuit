# 직류 계산 비용과 남은 한계

## 계산 예산을 둔 이유

2026-10-02 Windows / Ryzen 5 5600X / Node 24에서 측정했다. 일반 수업 예제는 빨랐지만 큰 분모·복잡한 연결망의 정확 소거는 수 초 동안 동기 계산을 점유했다. 이 결과를 근거로 [ADR-025](../../decisions/ADR-025-bounded-approximate-dc.md)의 4,096비트·GCD 나머지 연산 1,000,000회 예산과 검증된 근사 경로를 도입했다.

| 사례 | 예산 도입 전 중앙값 | 도입 후 중앙값 | 결과 |
|---|---:|---:|---|
| 일반 25절점 격자 | 29.69ms | 34.07ms | 정확 |
| 일반 49절점 격자 | 303.86ms | 134.29ms | 예산 후 근사 |
| 큰 분모 25절점 격자 | 6213.88ms | 127.09ms | 예산 후 근사 |
| 큰 저항비 25절점 격자 | 5266.78ms | 160.15ms | 불안정 근사 거부 |

당시 브리지 자동 조절 pipeline p95는 0.88ms였다. 30,030회 반복 갱신에서 정확한 KCL·전력과 큰 누적 힙 증가 부재를 확인했지만 실기기 전체의 응답성이나 누수 부재를 보장하는 수치는 아니다.

근거 원본은 [도입 전](results/2026-10-02-dc.json), [도입 후·반복 갱신](results/2026-10-02-bounded-dc.json), [최종 수치 정책·pipeline](results/2026-10-02-bounded-grid.json)에 보존한다. 다른 실행의 시간을 빼서 단계별 비용으로 해석하지 않는다.

## 재현과 한계

저장소 루트에서 실행한다. 결과 파일은 별도 임시 경로를 사용한다.

~~~sh
node --expose-gc tools/benchmark-dc.mjs report.json
node --expose-gc tools/benchmark-dc.mjs --case=grid grid-report.json
node --expose-gc tools/benchmark-dc.mjs --soak soak-report.json
~~~

- 계산 예산은 정확 연산의 폭주를 제한한다. 파싱·큰 행렬 메모리·근사 LU까지 포함한 전체 시간 상한이 아니다. Worker도 총 연산량 자체를 줄이지 않는다.
- 한 기기에서 얻은 수치로 제품 절점 수나 자릿수 제한을 정하지 않는다. 연결 형태와 수치 복잡도가 함께 비용을 결정한다.
- 저사양 기기·모바일·초기 3D 준비·장시간 UI/GPU 메모리는 별도 확인 대상이다. 브라우저 계측 도구는 tools/benchmark-browser.mjs에 남겨 재사용한다.
- 2026-10-08의 일시적 3D 지연은 로컬·배포판 모두 정상화되었고 원인은 미확정이다. 계산 병목이나 특정 개선의 효과로 단정하지 않는다.
