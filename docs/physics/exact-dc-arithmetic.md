# 정확 직류 연산 명세

기준: SIM-008, [ADR-024](../../decisions/ADR-024-exact-dc-arithmetic.md), [ADR-025](../../decisions/ADR-025-bounded-approximate-dc.md), 2026-10-02.

**채택 명세와 구현 상태를 구분한다.** 현재 런타임은 정확 유리수와 예산 초과 근사 해석, 회로 저장은 v6, 측정 기록은 v5다. §1~6의 정확 경로를 구현했고 [첫 비용 검증](../testing/exact-dc-performance.md)을 완료했다. §7의 요청별 계산 예산·명시적 근사 경로와 공통 품질 전달을 구현했다. 이전 형식의 변환·호환 경로는 제공하지 않는다.

## 1. 보장 범위

유한 소수·분수·SI 접두어로 주어진 이상적인 선형 직류 저항 회로에서 정확 해석을 기본으로 한다. 정확 경로에서 유일하게 결정되는 전위·전류·전력·등가저항은 반올림 없이 계산한다. §7의 계산 예산을 초과하면 품질 정보를 붙인 근사 해석을 허용한다. 기준점과 이상적인 0 Ω 요소·열린 경로의 취급은 기존 물리 모델과 ADR-003/009/011을 따른다. 어떤 경로도 미정인 전류나 기준점 없는 전위를 임의로 결정하지 않는다.

실제 부품의 불확실성, 화면 기하·애니메이션, 외부 측정값의 오차는 이 보장의 대상이 아니다. 향후 축전기·다이오드 등 다른 물리 모델의 해석 방식은 별도 결정한다.

앱의 독립 기준 정책은 [ADR-033](../../decisions/ADR-033-independent-references.md)에 따라 영역별로 표시된 원점만 고정한다. 이는 기준 없는 공통 전위를 물리적 절대값으로 확정하는 것이 아니다. 내부 전압차·전류·전력의 정확값과 실제 비유일성을 보존하고 다른 영역의 전압은 비교하지 않는다. 엔진 기본 `explicit` 정책의 기준 없는 결과는 유지한다.

## 2. 수치의 원본과 표현

### 실행 중 표현

입력과 정확 경로의 물리 스칼라는 `{ numerator: bigint, denominator: bigint }`로 표현한다. 생성과 모든 정확 연산 결과에서 다음 정규형을 유지한다. 근사 결과의 품질 구분은 §7을 따른다.

- 분모는 양수, 분자와 분모는 서로소다. 부호는 분자에만 둔다.
- 0은 항상 `0/1`이다. 음의 0은 없다.
- 덧셈·뺄셈·곱셈·나눗셈·절댓값·비교·부호·0 판정은 정수 연산으로 한다.
- 분모 0과 0으로 나누기는 유효한 수치가 아니다. Infinity·NaN을 유리수로 저장하지 않는다.

단위는 기존처럼 SI 기본 단위를 사용한다. 범용 기호 수식이나 임의 단위 대수 엔진을 도입하지 않는다.

### 저장과 입력

JSON 물리값은 `{ "numerator": "1", "denominator": "3" }`처럼 정규형 정수 문자열 쌍으로 저장한다. 좌표·회전·화면 배율 등 비물리 데이터는 기존 타입을 유지한다. v6의 voltageV·resistanceOhm·resistanceMinOhm·resistanceMaxOhm에 적용한다. number 물리값·비정규형 분수는 거부한다.

`CircuitDocument`의 해당 값이 유일한 물리 원본이다. 원문·표시 방식은 별도 표기 정보로 둘 수 있지만 서로 독립적으로 편집되는 number/분수 이중 원본을 만들지 않는다. 계산 결과와 UI 상태는 계속 문서 밖에 둔다.

quantity의 기존 BigInt 소수·분수·접두어 파서를 재사용하고, 마지막 binary64 변환을 제거한다. 예를 들어 `0.1/0.3`은 `1/3`, `10u`는 `1/100000`이다. 사용자가 확정하기 전의 불완전한 초안은 실제 값을 변경하지 않는다. 입력 길이 256자·개별 보정 지수 절댓값 4096 제한은 유지한다. binary64 표현 범위를 물리값의 유효성 기준으로 삼지 않는다. §7의 4,096비트 계산 예산은 입력 지수 제한과 다른 단위이며, 문서의 입력값을 잘라내거나 반올림하는 규칙이 아니다.

### 지원 형식

- 회로 v6와 측정 기록 v5만 읽고 쓴다. 이전 버전 변환, number 물리값·옛 분수 속성으로부터 값 복원은 제공하지 않는다.
- 관리하는 예제·fixture는 v6 자체로 검증한다. 사용자 저장본은 자동으로 변환하거나 삭제하지 않는다.
- 회로 저장·복사·실행 취소·기록 스냅샷은 같은 정규형 직렬화 경계를 사용한다. 측정 기록의 value도 정수 문자열 쌍이며 null은 계속 미정 상태를 뜻한다.
- 원시 CSV는 유한 소수는 정확한 소수, 순환소수는 정확한 분수 문자열로 내보낸다. 화면 측정표의 복사/CSV는 기존 표시 정책을 따른다.

## 3. 정확 계산 경로

`확정 입력 → 문서의 정확값 → 연결망의 정확 소자값 → MNA 정확 해 → 측정·기록의 정확값 → 표시`

1. ID 기반 연결망과 기준점을 기존 방식으로 만든다. 저항 범위·전원 제약 검증은 정확 비교를 사용한다. 같은 net의 단자는 같은 전위 값을 참조한다.
2. MNA의 계수·우변을 유리수로 구성한다. 저항의 `1/R`, 전원의 지정 전압과 0 V 제약에 중간 반올림을 넣지 않는다. 0 Ω은 기존 연결/제약 모델로 처리하며 `1/0`을 만들지 않는다.
3. 안정된 net·소자 순서로 소거한다. 피벗의 유무는 정확한 0으로 판정하고 선택 순서도 결정론적으로 정한다. 유일 해, 모순, 미정을 구분한다. 큰 저항비나 작은 피벗이라는 이유만으로 특이 행렬로 판정하지 않는다.
4. 전압원 제약의 불일치는 정확한 합으로 판정해 기존 `CONFLICTING_SOURCES` 등 의미에 맞는 진단을 반환한다. 정확히 일치하는 중복 제약이라도 전류가 유일하지 않다면 성공값을 만들어 내지 않는다. 기존 미정 회로 정책을 유지한다.
5. 결과를 원래 식에 대입한 잔차 `A·x−b`는 정확히 0이어야 한다. 잔차가 남으면 계산 실패로 처리하며 결과를 표시하거나 작은 값으로 덮지 않는다. 진단은 `EXACT_SOLVE_FAILED`이며 기존 구조화 Diagnostic 계약을 따른다.
6. 부품 전압 `Va−Vb`, 저항 전류 `V/R`, 전력 `V·I`도 정확값으로 계산한다. 공개 결과와 측정 API는 이 값을 전달하고 화면용 number만 있는 결과 계약을 대체한다.

자체 조밀 MNA 구조와 결정론적 첫 비영 피벗의 유리수 가우스 소거를 사용한다. 이후 분모를 제거한 정수 행렬의 분수 없는 소거로 교체할 수 있다. 선택은 내부 구현이며 정확성·결정론 계약은 같다. Bareiss 등 구체적인 최적화 전략은 비용 검증 전 필수 조건으로 고정하지 않는다.

## 4. 정확 경로의 측정과 물리 판정

| 대상 | 정확 연산 기준 |
|---|---|
| 전압 탐침 | 빨강 net 전위에서 검정 net 전위를 뺀다. 같은 전위면 정확히 0 V다. |
| 도선 전류 | 기존 도선 제거/그래프 절단과 KCL 방식을 재사용하되 모든 단자 전류를 유리수로 합산한다. 도선 고리는 계속 미정으로 구분한다. |
| 균형·방향 | 분자 0만 물리적 0이다. 비영 값의 크기와 무관하게 부호로 방향을 정한다. |
| 등가저항 | 전원 분리 정책을 유지하고 정확한 1 V 시험원·시험 전류의 비로 계산한다. 개방·단락·미정은 상태로 구분한다. |
| KCL·KVL·전력 | 유효한 해의 부호 있는 합이 정확히 0인지 확인한다. 기준점 변경 후 전압차·전류·전력이 정확히 보존된다. |
| 기록 | 당시 정확값·단위·방향·계산 조건·회로 스냅샷을 보존한다. 표시 반올림은 기록의 원본이 아니다. |

`SolveOptions`의 절대·상대 허용오차는 정확 경로의 0·제약 일치·특이성 판정에 사용하지 않는다. 현재 공개 타입에서 두 옵션을 제거했고 런타임에 옵션을 전달하면 `INVALID_SOLVE_OPTIONS`로 거부한다. 근사 경로의 수용 기준은 §7의 엔진 내부 정책이며, 삭제한 전역 물리 허용오차 옵션을 복원하지 않는다. 외부 측정 오차를 비교하는 허용범위는 별개다.

FIX-09의 12 V, R₁=100 Ω, R₂=R₃=200 Ω, VR₁=400 Ω, 중앙 R₅=100 Ω에서는 양쪽 중간 전위가 정확히 8 V, R₅ 및 양쪽 연결 도선 전류가 모두 정확히 0 A여야 한다. 399/401 Ω 등 실제로 불균형인 값에서는 작은 전류를 보존한다.

## 5. 표시와 실시간 조절 경계

정확 경로에서는 quantity가 정확값을 기존 자동 단위·유효 숫자·원래 숫자 정책으로 표시한다. 유한 소수는 필요 자릿수로 변환하고, 무한 순환소수는 표시 정밀도에 맞춰 반올림한다. 편집에 필요한 정확 원문은 분수로 복원할 수 있어야 한다. 엔진이 유리수를 쓰더라도 화면의 모든 측정값을 분수로 바꾸지는 않는다. 근사값의 구분·방향 신뢰도는 §7을 공통으로 적용한다.

색·높이·두께 등은 정확값으로 기준값과의 차·비를 구한 뒤 표시 가능한 number로 변환한다. 0 여부·방향·같은 전위의 판정은 변환 전에 결정해 두 렌더러가 공유한다. 원시 분자·분모를 각각 number로 바꿔 나누면 둘 다 무한대가 될 수 있으므로 공통 변환기가 크기를 조절해 비를 변환한다. 화면 해상도로 표현할 수 없는 비영 값도 물리적 0으로 재분류하지 않는다. 숫자는 정확값에서 지수 표기로 보존하며, 기하 변환의 범위 초과·비유한 값은 명시적으로 처리한다. 점열의 큰 간격·위상 계산 안정성은 별도 표시 책임으로 남는다.

현재 슬라이더는 N=1000의 정수 단계 `0 ≤ k ≤ N`, 양의 정수 단계 수 `N`에 대해 `min + (max−min)·k/N`을 정확히 계산한다. `k=0`에서 최솟값, `k=N`에서 최댓값이 정확히 재현된다. 단계 수는 조절기 설정이지 물리 엔진의 임의 허용오차가 아니다. 직접 입력한 정확값은 슬라이더를 움직이기 전에는 단계에 맞춰 바꾸지 않는다.

자동 조절의 시계·진행률은 UI의 number를 사용할 수 있다. 문서에 적용할 때 정수 단계로 확정해 같은 공통 값 생성기를 사용한다. 별도 소수 정밀도 정책을 쓰는 조절기는 확정한 10진 문자열을 quantity로 파싱한다. 이진 계산의 잔여 자릿수를 그대로 물리 입력으로 저장하지 않는다. 구체적인 단계 수·갱신 주기는 후속 성능 검증에서 조정하되, UI의 보간값이 측정값을 대신하지 않는다.

## 6. 모듈 경계와 검증

- `domain`: 최소 정확값 타입·직렬화 계약, 문서 검증과 버전 이행. 물리 계산 결과는 저장 문서 밖에 둔다.
- 순수 유리수 연산 모듈: 정규화·사칙연산·비교·변환. 회로·단위·UI를 알지 않는다. domain의 타입만 참조하고 domain은 이 구현에 의존하지 않는다.
- `quantity`: 기존 입력 문법·단위와 표시 반올림을 담당한다.
- `connectivity` / `simulation` / `measurement`: 기존 책임을 유지하며 정확값을 전달한다. 행렬은 simulation 내부에만 둔다.
- `visualization` / `app`: 정확한 물리 판정 결과와 표시용 근삿값을 소비한다. React·SVG·Three.js가 물리 계산에 들어오지 않는다.

현재 fixture를 재사용해 브리지의 부품·양쪽 도선 0, 실제 작은 전류와 방향, 분수 입력부터 기록까지의 일관성, KCL/KVL/전력·기준점 불변성, 모순/미정 회로, 저장 왕복·지원 밖 버전 거부를 확인한다. 정확 기대값은 입력과 해석적 관계에서 작성하고 기존 number 결과를 다시 유리수로 포장해 기준으로 삼지 않는다. 기존 허용오차 fixture는 근사 표시의 비교 근거로 유지할 수 있지만 정확 연산 보장의 증거를 대신하지 않는다.

2026-10-02의 [비용 검증](../testing/exact-dc-performance.md)에서 일반 예제의 계산·자동 조절과 반복 갱신은 원활했으나, 큰 연결망과 분모가 결합하면 수 초의 동기 계산 지연이 확인됐다. 이후 사용자 합의로 §7의 계산 예산과 명시적 근사 경로를 채택했다. 구현된 경로는 수용할 수 없는 근사 결과를 실패로 반환한다. 이전 해를 새 입력의 결과로 표시하지 않는다.

### 구현 내부 경계

`rational/conversion`은 단위 없는 10진 토큰 해석과 화면용 binary64 변환을 소유하고, quantity는 이를 재사용해 분수·SI 단위 문법과 표시를 처리한다. domain에는 최소 타입과 저장 정규형 검증만 둔다. `visualization/potential`은 정확 전위와 표시 좌표·축 단위 변환을 함께 관리한다. 2D 범례와 3D 눈금은 같은 공개 변환 함수를 사용하고, 숫자 표시는 정확 전위를 사용한다. 3D 높이 맞춤과 장면 경계는 같은 눈금 계산을 재사용한다.

## 7. 계산 예산과 근사 해석

### 7.1 목적과 한도

일반 수업 회로의 정확 계산을 우선하며, 저사양 기기에서 일부 프레임 저하가 생길 수 있는 넉넉한 경계를 둔다. 복잡한 입력으로 정확 계산이 수 초 동안 이어지는 상황은 근사 해석으로 전환한다. 전압·저항의 물리적 크기나 부품 개수만으로 전환하지 않는다.

| 항목 | 채택한 초기 예산 | 판정 |
|---|---:|---|
| 중간 정수 크기 | 4,096비트 | 분자·분모 및 약분 피연산자의 절댓값이 최대 4,096비트이면 허용 |
| 약분 연산량 | 1,000,000회 | GCD의 내부 나머지 연산을 최대 1,000,000회까지 허용 |

- 4,097비트 피연산자의 고비용 약분에 들어가기 전, 또는 1,000,001번째 나머지 연산을 수행하기 전에 정확 경로를 중단한다. 0의 비트 수는 0으로 센다. 비트 수는 부호를 제외하며 정규화 전 분자·분모도 검사한다.
- 약분 함수 호출 횟수나 유리수 생성 횟수가 아니라 유클리드 알고리즘 내부의 나머지 연산 한 번을 한 회로 센다. 정확 비교·교차 약분·입력 검증에 사용되는 같은 연산도 정확 해석 안에서는 포함한다.
- 예산은 한 번의 `SimulationEngine.solve` 요청에 속한다. 정확 수치 검사·MNA 구성·소거·정확 잔차 검사·부품 결과 생성까지 공유하며 단계마다 초기화하지 않는다. 등가저항의 시험 회로 해석에도 동일한 정책을 적용한다.
- 순수한 입력 파싱·문서 저장의 제한과 해석 예산을 구분한다. 회로 원본의 값을 잘라내거나 바꾸지 않는다. 전체 문서 파싱·행렬 할당·근사 계산의 최악 비용까지 두 한도만으로 제한하는 것은 아니다.
- 시계·FPS·기기 종류·이전 조절값의 계산 경로를 사용하지 않는다. 안정된 소자/절점 순서와 동률 처리 순서를 유지한다. 한도 및 계산 알고리즘 개정은 명시적으로 관리하고 경계 fixture를 다시 확인한다.

후보 계측에서 브리지는 GCD 반복 572회, 일반 25절점 격자는 341,300회였다. 작은 고비용 사례의 약 50~70ms 계산도 완료했고, 기존 5~6초 사례는 약 120~135ms에 정확 경로를 중단했다. [계측 근거](../testing/exact-dc-performance.md)의 시간은 근사 풀이 비용을 포함하지 않으며 저사양 기기에서의 고정 응답 시간 보장이 아니다.

### 7.2 전환과 실패의 구분

계산 예산 초과만 근사 전환을 허용한다. 정확하게 확인한 `SOURCE_SHORT`, `CONFLICTING_SOURCES`, `FLOATING_SUBCIRCUIT`, `SINGULAR_SYSTEM`과 `EXACT_SOLVE_FAILED`를 근사 계산으로 덮지 않는다. 전원 모순 등 필수 전기적 유효성 검사가 예산 때문에 완료되지 않았다면 검증되지 않은 근사 해를 성공으로 반환하지 않는다.

부분적으로 소거한 정확 행렬이나 이전 입력의 해를 이어 쓰지 않고, 동일 입력의 원래 회로식에서 근사 해석을 시작한다. 결과는 한 번의 해석에 대해 정확 또는 근사 중 하나이며, 정확 결과 맵과 근사 결과 맵을 설명 없이 섞지 않는다.

구조화 진단은 다음과 같다.

| 코드 | 의미 |
|---|---|
| `APPROXIMATE_SOLUTION` | 수용된 근사 해. 전환 이유 `integer-limit` 또는 `operation-limit`와 적용 정책을 전달 |
| `APPROXIMATE_SOLVE_FAILED` | 표현 범위 초과, 검증 미완료, 수치적 불안정, 잔차/오차 추정 실패 등으로 근사 해를 수용하지 못함 |

진단은 관련 요소 ID와 구조화된 사유를 반환한다. 수치적으로 풀지 못했다는 사실을 물리적 단락·개방이나 정확한 특이성의 증거로 취급하지 않는다.

### 7.3 근사 알고리즘

1. **공통 회로식과 스케일 조정.** 같은 연결망·기준점·MNA 구성 규칙을 사용한다. 입력 원본에서 행·열 배율을 조정한 뒤 binary64로 변환하고, 해를 원래 단위로 복원한다. 원시 분자·분모를 각각 number로 바꾸어 Infinity/Infinity가 생기는 경로를 만들지 않는다. 필요한 계수나 해를 표현할 수 없으면 범위 실패로 반환한다. 작은 저항을 임의 단락으로, 큰 저항을 임의 개방으로 바꾸지 않는다.
2. **부분 피벗 LU 분해.** 스케일을 조정한 행렬에서 크기가 큰 피벗을 선택하며, 동률이면 안정된 기존 순서를 따른다. 정확 엔진의 첫 비영 피벗 규칙을 부동소수점에 그대로 적용하지 않는다.
3. **잔차 보정.** 해를 회로식에 대입해 잔차를 구하고, 같은 LU 분해를 재사용해 최대 2회 보정한다. 수용 기준에 도달하면 종료하며 개선되지 않는 보정을 반복하지 않는다. 새로운 무제한 BigInt 계산을 보정 과정에 도입하지 않는다.
4. **수용 검사.** 행별 크기를 고려한 잔차/후방오차, 조건수 등 수치적 민감도의 추정, 값의 유한성을 함께 확인한다. 대표 잔차 척도는 `max_i |(A·x−b)_i| / (Σ_j |A_ij|·|x_j| + |b_i|)`다. 분모 0·언더플로와 스케일 복원을 명시적으로 처리하며, 원래 식에 대한 수용 의미를 보존한다. 작은 잔차 하나만으로 충분히 정확한 해라고 판정하지 않는다.

구체적인 수용 정책과 검증은 §7.6을 따른다. 화면 유효 숫자나 임의의 절대 `1e-9 A` 같은 기준을 엔진 전체의 물리적 0 판정으로 사용하지 않는다.

참고: [LAPACK DGESVX](https://netlib.org/lapack/explore-html/d5/dbe/group__gesvx_ga82173a93234afc15d70b64233b3e5bc8.html)의 행·열 equilibration, 부분 피벗 LU, iterative refinement, error/condition estimates. 알고리즘 구성의 참고이며 라이브러리 추가 의무는 아니다.

### 7.4 결과·측정·표시의 공통 품질

- `SimulationResult`와 측정 결과는 정확/근사를 명시적으로 구분한다. 근사 결과에는 전환 이유·수용 검사 근거와 측정량의 오차/방향 판단에 필요한 정보를 전달한다. 전역 잔차 숫자 하나를 모든 가지 전류의 절대 오차로 사용하지 않는다.
- 전압차·부품 전류·전력·도선 KCL 합·등가저항은 해당 경로의 품질을 유지하고 추정 오차를 전파한다. 이미 얻은 근사값을 다시 유리수로 표현하더라도 물리적으로 정확한 결과로 승격되지 않는다.
- 추정 오차 범위가 0을 포함해 전류 부호를 판별할 수 없으면 방향 불확실로 전달한다. 해당 방향성 입자를 생략하며, 작은 계산 잔여량을 최소 굵기의 흐름으로 부풀리지 않는다. 수치 자체를 정확한 0으로 덮거나 연결망을 끊지 않는다. 도선 고리의 물리적 미정과도 구분한다.
- 정확 경로에서는 §4의 정확한 0·미세 비영 구분을 유지한다. 근사 경로의 KCL/KVL·보존식 검사는 정확 등식 성립 표시와 구분한다.
- 근사 측정값에 `≈`를 붙인다. 입력한 전지·저항의 정확 속성값에는 붙이지 않는다. 2D·3D의 측정 수치·축과 전류 상태는 같은 품질/형식화 규칙을 사용하며, 별도의 설명 밴드나 상시 개발자 안내를 추가하지 않는다.
- 기록·새로고침 복원·복사·CSV에서도 정확/근사 구분과 당시 품질을 보존한다. 저장 표현을 위해 반올림한 근사값이 정확값으로 읽히지 않도록 한다. `CircuitDocument`에는 계산 결과·품질을 넣지 않는다.
- 측정 기록 v5만 지원한다. record.quality는 exact 또는 approximate이며, 근사 스칼라의 approximation(reason, policy, absoluteError)과 일치해야 한다. 복원 시 누락·불일치를 거부한다. v3 변환·복원 경로는 제공하지 않으며 이전 저장 키를 삭제하지 않는다.

### 7.5 구현 경계와 수용 검증

simulation은 요청별 예산·공통 회로식 구성·정확/근사 풀이·수용 검사·구조화 결과를 소유한다. rational은 순수 연산을 유지하고 필요한 계수는 해석 요청에 귀속시켜 전달한다. 모듈 전역 카운터, 브라우저 시계, 소비자가 행렬을 직접 다루는 경로를 만들지 않는다. domain에는 공유 품질 타입, measurement에는 측정 파생값과 오차 전파, quantity/visualization에는 공통 표시 판정을 둔다. 2D·3D·기록이 따로 근사 전환이나 허용오차를 정하지 않는다.

아래 수용 기준은 tests/bounded-dc.test.ts와 기존 정확 연산·측정·표시 테스트, 부하 보고서로 확인한다.

1. 한도 바로 아래·같음·초과와 GCD 내부 반복 계수를 검사한다. 단계별 재설정 없이 같은 입력이 같은 경로·진단을 반환해야 한다.
2. 일반 fixture와 브리지의 0/미세 불균형은 정확 경로를 유지한다. 한도를 넘는 회로는 근사로 전환하고 원래 입력은 보존한다.
3. 근사 결과를 알려진 해·검증 가능한 정확 해와 비교한다. 잔차만 작고 민감도가 큰 사례, 범위 초과, 모순·미정 및 보정 실패를 성공으로 내보내지 않는다.
4. 근사 표시·기록 저장/복원·CSV와 방향 불확실 판정이 공통으로 보존되는지 확인한다. 2D·3D의 흐름이 서로 다른 임계값을 사용하지 않아야 한다.
5. 기존 느린 사례에서 정확 경로 중단 시간뿐 아니라 근사 풀이·검증·표시 준비를 포함한 전체 비용을 다시 측정한다. 고정 FPS를 CI 통과 조건으로 추가하지 않는다.


### 7.6 구현된 수치 정책 `dc-budget-1`

- `simulation/mna`는 원래 회로식의 개별 stamp를 생성한다. 정확 풀이가 유리수로 합산하고 근사 풀이는 같은 stamp를 다시 읽는다. 행별 최대 절댓값, 이어서 열별 최대 절댓값으로 두 배율을 **binary64 변환 전에** 적용한다. 이때 큰 정수 비를 약분 없이 공통 안전 변환기로 읽으며 근사 계산 중 무제한 정확 소거를 재시도하지 않는다. 자기 net으로 되돌아오는 저항의 stamp는 상쇄되어 생략한다.
- 부분 피벗 LU는 같은 크기에서 먼저 나온 행을 선택한다. 잔차 보정은 후방오차가 `8·EPSILON`보다 클 때만 최대 2회 시도하고 개선되지 않으면 이전 해를 유지한다.
- 작은 조밀 행렬의 LU를 재사용해 역행렬 열을 구한다. 조건수 추정은 `κ∞ = ||A||∞·||A⁻¹||∞`다. `γ = (n + m + 4)·EPSILON`에서 n은 미지수 수, m은 한 행에 합산하는 최대 stamp 수다. `κ∞·γ > 1e-6`이면 수치적 불안정으로 거부한다. 후방오차는 `32·γ` 이하이고 모든 값은 유한해야 한다. 이 상대 기준을 전류의 물리적 0 판정에 사용하지 않는다.
- 변수별 추정 절대 오차는 스케일된 식에서 `4·|A⁻¹|·(|b−Ax| + γ·(|A|·|x|+|b|))`로 계산하고 열 배율을 복원한다. 보수적 수치 오차 추정이며 증명된 구간 연산의 상한을 뜻하지 않는다. 해·추정 오차의 overflow/underflow는 범위 실패로 처리한다.
- 스칼라는 기존 분자·분모 운반 형식을 재사용한다. `approximation`이 없으면 정확값이고, 있으면 `{reason, policy:'dc-budget-1', absoluteError}`가 필수다. 근사 해를 이 형식에 담아도 정확값으로 승격되지 않는다. 성공 `SimulationResult.quality`는 exact/approximate와 후자의 조건수·후방오차·보정 횟수를 명시한다. 실패 결과에는 값 맵과 품질이 없다.
- 순수 rational 연산이 메타데이터를 전파한다. 덧셈/뺄셈은 오차 합, 곱셈은 `|a|·δb + |b|·δa + δa·δb`, 역수는 `δb/(|b|·(|b|−δb))`를 사용한다. 분모의 오차 범위에 0이 포함되면 신뢰할 수 없는 오차로 전달하여 유효한 등가저항으로 반환하지 않는다. 원본 정확값의 사칙연산 규칙은 변하지 않는다.
- `q.direction`이 오차 범위 내 0 포함 여부를 공통 판정한다. 전류 모델의 uncertain은 도선 고리의 undefined와 다르다. 2D/3D 띠·점열 및 센서 화살표를 생략하며 측정 수치는 ≈와 함께 보존한다. KCL/KVL은 approximate 표식과 실제 추정 허용범위를 반환한다.
- 기록 v5는 당시 품질과 오차를 저장한다. 원시 CSV는 quality/approximation 열과 ≈를 포함하며 사용자용 측정표·복사에는 ≈와 방향 불확실 표시를 유지한다. 회로 v6 스키마는 계산 품질 속성을 허용하지 않는다.
- 검증: 25절점 작은 분모 회로는 정확 경로, 같은 회로에 80자리 분모를 더한 경우는 정확 기준 해와 추정 오차 내 일치, 49절점 회로는 연산량 한도로 전환했다. ±400 지수의 계수 스케일과 알려진 해, 작은 잔차에도 민감도가 큰 행렬의 거부, 예산 경계·결정론·근사 기록 왕복·방향 불확실을 검사한다. [부하 보고서](../testing/exact-dc-performance.md)의 최신 결과를 함께 따른다.
