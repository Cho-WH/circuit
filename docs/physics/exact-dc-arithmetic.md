# 정확 직류 연산 명세

기준: SIM-008, [ADR-024](../../decisions/ADR-024-exact-dc-arithmetic.md), 2026-10-02.

**채택된 구현 기준이며 아직 엔진에 반영되지 않았다.** 현재 런타임은 number 기반, 저장 문서는 v4다. 이 문서의 정확값 계약으로 전환할 때 공개 타입·스키마·순차 마이그레이션·관련 테스트를 함께 갱신한다. 연산 비용과 실시간 부하는 후속 검증으로 남긴다.

## 1. 보장 범위

유한 소수·분수·SI 접두어로 주어진 이상적인 선형 직류 저항 회로에서, 유일하게 결정되는 전위·전류·전력·등가저항을 반올림 없이 계산한다. 기준점과 이상적인 0 Ω 요소·열린 경로의 취급은 기존 물리 모델과 ADR-003/009/011을 따른다. 정확 연산이 미정인 전류나 기준점 없는 전위를 임의로 결정하지는 않는다.

실제 부품의 불확실성, 화면 기하·애니메이션, 외부 측정값의 오차는 이 보장의 대상이 아니다. 향후 축전기·다이오드 등 다른 물리 모델의 해석 방식은 별도 결정한다.

## 2. 수치의 원본과 표현

### 실행 중 표현

물리 스칼라는 `{ numerator: bigint, denominator: bigint }`로 표현한다. 생성과 모든 연산 결과에서 다음 정규형을 유지한다.

- 분모는 양수, 분자와 분모는 서로소다. 부호는 분자에만 둔다.
- 0은 항상 `0/1`이다. 음의 0은 없다.
- 덧셈·뺄셈·곱셈·나눗셈·절댓값·비교·부호·0 판정은 정수 연산으로 한다.
- 분모 0과 0으로 나누기는 유효한 수치가 아니다. Infinity·NaN을 유리수로 저장하지 않는다.

단위는 기존처럼 SI 기본 단위를 사용한다. 범용 기호 수식이나 임의 단위 대수 엔진을 도입하지 않는다.

### 저장과 입력

JSON 물리값은 `{ "numerator": "1", "denominator": "3" }`처럼 정규형 정수 문자열 쌍으로 저장한다. 좌표·회전·화면 배율 등 비물리 데이터는 기존 타입을 유지한다. 필드별 적용은 새 스키마 버전에서 확정하며 현재 v4에 이 객체를 그대로 추가하지 않는다.

`CircuitDocument`의 해당 값이 유일한 물리 원본이다. 원문·표시 방식은 별도 표기 정보로 둘 수 있지만 서로 독립적으로 편집되는 number/분수 이중 원본을 만들지 않는다. 계산 결과와 UI 상태는 계속 문서 밖에 둔다.

quantity의 기존 BigInt 소수·분수·접두어 파서를 재사용하고, 마지막 binary64 변환을 제거한다. 예를 들어 `0.1/0.3`은 `1/3`, `10u`는 `1/100000`이다. 사용자가 확정하기 전의 불완전한 초안은 실제 값을 변경하지 않는다. 입력 길이 256자·개별 보정 지수 절댓값 4096 제한은 유지한다. binary64 표현 범위를 물리값의 유효성 기준으로 삼지 않으며 정수 크기·자원 한도의 추가 제한은 후속 검증에서 정한다.

### 기존 자료의 이행

- v1→v4의 기존 변환 뒤 새 버전 변환을 연결한다. 원본을 변경하지 않고 새 문서를 반환한다.
- v4에서 기존 검증을 통과하는 명시적 분수 속성은 정확히 파싱하여 우선 보존한다. 분수와 수치의 일치 여부는 당시 계약으로 검증한다.
- number만 남은 값은 `Number.toString()`의 가장 짧은 왕복 가능한 10진 문자열을 정확히 파싱한다. 기존 이진값의 정수 비율이나 추정한 단순 분수로 바꾸지 않는다. `0.3333333333333333`을 임의로 `1/3`으로 복원하지 않는다.
- 회로 저장·복사·공유·실행 취소·기록 스냅샷이 같은 직렬화 경계를 쓴다. 별도 측정 기록 저장소도 버전을 구분해 이행한다. 과거 number 측정값은 위 10진 정책으로 보존하며 정확 엔진이 계산한 과거 결과로 소급해 간주하지 않는다.

## 3. 계산 경로

`확정 입력 → 문서의 정확값 → 연결망의 정확 소자값 → MNA 정확 해 → 측정·기록의 정확값 → 표시`

1. ID 기반 연결망과 기준점을 기존 방식으로 만든다. 저항 범위·전원 제약 검증은 정확 비교를 사용한다. 같은 net의 단자는 같은 전위 값을 참조한다.
2. MNA의 계수·우변을 유리수로 구성한다. 저항의 `1/R`, 전원의 지정 전압과 0 V 제약에 중간 반올림을 넣지 않는다. 0 Ω은 기존 연결/제약 모델로 처리하며 `1/0`을 만들지 않는다.
3. 안정된 net·소자 순서로 소거한다. 피벗의 유무는 정확한 0으로 판정하고 선택 순서도 결정론적으로 정한다. 유일 해, 모순, 미정을 구분한다. 큰 저항비나 작은 피벗이라는 이유만으로 특이 행렬로 판정하지 않는다.
4. 전압원 제약의 불일치는 정확한 합으로 판정해 기존 `CONFLICTING_SOURCES` 등 의미에 맞는 진단을 반환한다. 정확히 일치하는 중복 제약이라도 전류가 유일하지 않다면 성공값을 만들어 내지 않는다. 기존 미정 회로 정책을 유지한다.
5. 결과를 원래 식에 대입한 잔차 `A·x−b`는 정확히 0이어야 한다. 잔차가 남으면 계산 실패로 처리하며 결과를 표시하거나 작은 값으로 덮지 않는다. 관련 진단의 코드와 스키마는 구현 시 함께 확정한다.
6. 부품 전압 `Va−Vb`, 저항 전류 `V/R`, 전력 `V·I`도 정확값으로 계산한다. 공개 결과와 측정 API는 이 값을 전달하고 화면용 number만 있는 결과 계약을 대체한다.

자체 조밀 MNA 구조를 재사용한다. 유리수 소거 또는 분모를 제거한 정수 행렬의 분수 없는 소거를 사용할 수 있다. 선택은 내부 구현이며 정확성·결정론 계약은 같다. Bareiss 등 구체적인 최적화 전략은 비용 검증 전 필수 조건으로 고정하지 않는다.

## 4. 측정과 물리 판정

| 대상 | 정확 연산 기준 |
|---|---|
| 전압 탐침 | 빨강 net 전위에서 검정 net 전위를 뺀다. 같은 전위면 정확히 0 V다. |
| 도선 전류 | 기존 도선 제거/그래프 절단과 KCL 방식을 재사용하되 모든 단자 전류를 유리수로 합산한다. 도선 고리는 계속 미정으로 구분한다. |
| 균형·방향 | 분자 0만 물리적 0이다. 비영 값의 크기와 무관하게 부호로 방향을 정한다. |
| 등가저항 | 전원 분리 정책을 유지하고 정확한 1 V 시험원·시험 전류의 비로 계산한다. 개방·단락·미정은 상태로 구분한다. |
| KCL·KVL·전력 | 유효한 해의 부호 있는 합이 정확히 0인지 확인한다. 기준점 변경 후 전압차·전류·전력이 정확히 보존된다. |
| 기록 | 당시 정확값·단위·방향·계산 조건·회로 스냅샷을 보존한다. 표시 반올림은 기록의 원본이 아니다. |

`SolveOptions`의 절대·상대 허용오차는 이 엔진의 0·제약 일치·특이성 판정에 사용하지 않는다. 공개 타입 전환 시 이 옵션을 제거하거나 다른 근사 엔진 전용으로 명확히 분리한다. 외부 측정 오차를 비교하는 허용범위는 별개다.

FIX-09의 12 V, R₁=100 Ω, R₂=R₃=200 Ω, VR₁=400 Ω, 중앙 R₅=100 Ω에서는 양쪽 중간 전위가 정확히 8 V, R₅ 및 양쪽 연결 도선 전류가 모두 정확히 0 A여야 한다. 399/401 Ω 등 실제로 불균형인 값에서는 작은 전류를 보존한다.

## 5. 표시와 실시간 조절 경계

quantity가 정확값을 기존 자동 단위·유효 숫자·원래 숫자 정책으로 표시한다. 유한 소수는 필요 자릿수로 변환하고, 무한 순환소수는 표시 정밀도에 맞춰 반올림한다. 편집에 필요한 정확 원문은 분수로 복원할 수 있어야 한다. 엔진이 유리수를 쓰더라도 화면의 모든 측정값을 분수로 바꾸지는 않는다.

색·높이·두께 등은 정확값으로 기준값과의 차·비를 구한 뒤 표시 가능한 number로 변환한다. 0 여부·방향·같은 전위의 판정은 변환 전에 결정해 두 렌더러가 공유한다. 원시 분자·분모를 각각 number로 바꿔 나누면 둘 다 무한대가 될 수 있으므로 공통 변환기가 크기를 조절해 비를 변환한다. 화면 해상도로 표현할 수 없는 비영 값도 물리적 0으로 재분류하지 않는다. 숫자는 정확값에서 지수 표기로 보존하며, 기하 변환의 범위 초과·비유한 값은 명시적으로 처리한다. 점열의 큰 간격·위상 계산 안정성은 별도 표시 책임으로 남는다.

슬라이더는 정수 단계 `0 ≤ k ≤ N`, 양의 정수 단계 수 `N`에 대해 `min + (max−min)·k/N`을 정확히 계산한다. `k=0`에서 최솟값, `k=N`에서 최댓값이 정확히 재현된다. 단계 수는 조절기 설정이지 물리 엔진의 임의 허용오차가 아니다. 직접 입력한 정확값은 슬라이더를 움직이기 전에는 단계에 맞춰 바꾸지 않는다.

자동 조절의 시계·진행률은 UI의 number를 사용할 수 있다. 문서에 적용할 때 정수 단계로 확정해 같은 공통 값 생성기를 사용한다. 별도 소수 정밀도 정책을 쓰는 조절기는 확정한 10진 문자열을 quantity로 파싱한다. 이진 계산의 잔여 자릿수를 그대로 물리 입력으로 저장하지 않는다. 구체적인 단계 수·갱신 주기는 후속 성능 검증에서 조정하되, UI의 보간값이 측정값을 대신하지 않는다.

## 6. 모듈 경계와 구현 시 검증

- `domain`: 최소 정확값 타입·직렬화 계약, 문서 검증과 버전 이행. 물리 계산 결과는 저장 문서 밖에 둔다.
- 순수 유리수 연산 모듈: 정규화·사칙연산·비교·변환. 회로·단위·UI를 알지 않는다. domain의 타입만 참조하고 domain은 이 구현에 의존하지 않는다.
- `quantity`: 기존 입력 문법·단위와 표시 반올림을 담당한다.
- `connectivity` / `simulation` / `measurement`: 기존 책임을 유지하며 정확값을 전달한다. 행렬은 simulation 내부에만 둔다.
- `visualization` / `app`: 정확한 물리 판정 결과와 표시용 근삿값을 소비한다. React·SVG·Three.js가 물리 계산에 들어오지 않는다.

구현 시 기존 fixture를 재사용해 브리지의 부품·양쪽 도선 0, 실제 작은 전류와 방향, 분수 입력부터 기록까지의 일관성, KCL/KVL/전력·기준점 불변성, 모순/미정 회로, 저장 왕복·이전 버전 이행을 확인한다. 정확 기대값은 입력과 해석적 관계에서 작성하고 기존 number 결과를 다시 유리수로 포장해 기준으로 삼지 않는다. 기존 허용오차 fixture는 근사 표시의 비교 근거로 유지할 수 있지만 정확 연산 보장의 증거를 대신하지 않는다.

후속 비용 검증은 일반 수업 회로와 큰 회로, 저항비가 큰 회로, 수동·자동 연속 조절에서 해석 시간·중간 정수 크기·메모리·화면 응답을 확인한다. 현재 성능이 충분하다고 가정하지 않는다. 필요한 자원 제한과 구조화 실패 진단은 그 결과로 정하며, 실패 시 미정 상태를 전달한다. 부동소수점 계산으로 자동 우회하거나 이전 해를 새 입력의 결과로 표시하지 않는다.
